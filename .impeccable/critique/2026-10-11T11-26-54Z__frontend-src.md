## 디자인 고유성

커트 날짜·사진·D+경과·원하는 변화가 이어지는 구조는 SALU에 맞는 설계. 청록색과 차분한 톤은 현재 정체성으로 유지하는 방향이 적합. 앱 사용감을 높이려면 입력 순서와 주 행동의 위치를 개선할 필요. 새로운 장식이나 토스 화면을 복제하는 작업은 이번 검토의 권고가 아님.

정적 detector는 0건을 반환했지만, 브라우저 DOM 검사에서는 low-contrast와 nested-cards 경고가 발생. 저대비는 공통 색상과 실제 표시를 대조해 확인. 중첩 카드라는 이유만으로 오류로 분류하지 않았으며, 작성 화면의 긴 정보 순서 문제와 구분.

## 유지할 부분

- 홈의 간결한 설명과 가장 눈에 띄는 기록 시작 버튼. 예시 탐색을 보조 경로로 제공해 진입 부담을 낮추는 구성
- 기록·경과·사진에서 참고할 일부를 명시적으로 고르는 흐름. 선택하지 않은 원본과 준비에 포함할 자료의 구분
- 모바일 하단 메뉴, 작성 재진입 경로, 프로필 핵심 정보와 접힌 소속·후기 상세. 관찰한 화면에서 가로 넘침 없음

**영향:** 사용자는 서버가 계속 실패 중인지, 자신이 무엇을 해야 하는지 판단하기 어려움. 데이터가 사라지는 문제로 재현한 것은 아니며 저장 상태 표시의 문제.

**수정 방향:** 서버 연결 오류와 기기 저장 오류를 구분. 조회·동기화 성공 시 해당 서버 오류를 해제하고, 변경 대기·충돌·기기 저장 실패 상태는 실제 상태에 맞게 유지. 안내가 자동 재시도를 설명하도록 수정하고 수동 재시도 제공 여부 결정. 목록 조회 성공만으로 아직 보내지 않은 변경을 서버 저장 완료로 표시하지 않도록 주의.

원본 ▸ 서버 저장을 다시 시도해 주세요. 기기에 저장한 기록은 유지됩니다.  
진단 ▸ 동작 불일치·높임 흔들림: 자동 재시도가 있는데 사용자가 누를 재시도 버튼이 없음. 목록 조회 실패도 같은 문구로 표시  
추천 ▸ 계정 저장을 확인하지 못했어요. 잠시 후 다시 확인할게요.  
대안 ▸ 서버 연결을 다시 확인할게요. 기기에 저장한 기록은 그대로 있어요.  
이유 ▸ 조회/연결 상태와 자동 재시도 동작을 설명. 기기 저장 실패와 구분해야 하며 오류 상태 복구 수정과 함께 적용

## 작은 관찰과 기능 경계

- 일부 링크는 19–22px, 예시 초기화는 27px 높이, 선택 chip은 약 41px. 44px 터치 권장 크기 확대 후보. 크기만으로 WCAG 2.2의 24px 최소·간격 예외 위반을 단정하지 않음. 모바일 하단 메뉴는 68px, 날짜 버튼 44px, 저장/취소 48px로 충분한 크기 확인
- 경과는 홈의 손질 설명으로 의미를 보완하고 있음. 첫 경과 작성 안내는 `커트 후 달라진 점`처럼 쉬운 표현을 함께 사용하는 개선 후보
- 실제 등록 디자이너 목록·관리, 상담 송수신·답변·내역, 후기 작성, 커뮤니티는 후속 기능. 이전 담당자 이름/매장 재사용과 가상 프로필을 실제 디자이너 카탈로그 완료로 해석하지 않음. 프론트 전체 완료 상태가 아님
- 성능 실측·Safari·실물 모바일 키보드·200% 확대·스크린리더·실제 소셜 로그인·계정 저장 장애 복구는 이번 검토 범위 밖. 앞선 80개 화면 E2E/11개 인증 테스트 기록을 이번 새 실행 결과로 보고하지 않음

## 다음 수정 방향을 정할 항목

1. 수정 범위: `저장 상태·대비·문구 우선` / `모바일 작성 구조까지 함께`
2. 작성 방식: `한 화면에 핵심 입력 + 선택 정보 접기` / `입력 항목별로 순서대로 이동`

Impeccable 명령을 사용자가 하나씩 고를 필요는 없음. 요청과 이 검토의 우선순위에 맞춰 필요한 명령만 선택. 저장 상태는 harden, 정보 축소는 distill, 모바일 배치는 adapt, 문구는 ux-writing-kr와 clarify, 수정 후 마감은 polish로 연결 가능한 상태.
