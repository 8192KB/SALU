# SALU 정보 구분과 화면 위계 검토

뒤로가기와 제목의 한 줄 배치는 구현 의도였지만, 화면 전반의 구분감을 충분히 만드는 데 실패한 부분이 있음. 조원 목업을 복사하기보다 뒤로가기 문구 유지·별도 줄 배치, 관련 정보 묶음, 선택 상태와 주 행동의 명확한 구분을 적용하는 방향. 이번 검토는 현재 소스와 실제 렌더링 근거이며 UI 수정은 하지 않음.

## 디자인 판단과 강점

청록·흰색과 날짜별 개인 기록은 SALU의 차분한 기록 도구 방향에 맞음. 전체가 무관한 제품용 템플릿은 아니지만 커트 입력·상세·준비의 정보 묶음 규칙이 달라 앱의 통일감이 약함. 사진 포함 선택 카드, 체크·테두리·배경을 함께 쓰는 선택 표시, 저장 전 확인과 별도의 완료 결과는 유지할 강점. 참고 목업의 실제 전달 완료 문구는 아직 전송하지 않는 SALU에 적용 불가.

## 우선 문제

1. **P1 — 뒤로가기·제목·설명의 역할과 정렬 혼재.** `components.tsx:104`, `interface.css:1284`의 flex row에 13px 뒤로가기와 32px PC 제목 배치. 설명의 고정 margin-left 56px 때문에 자료 선택의 제목/설명 시작점이 약 51px 차이. 모바일은 문구를 숨김(`interface.css:1566`). 뒤로가기 문구를 한 줄에 유지하고, 다음 줄 제목과 설명을 같은 좌측 기준선에 배치. 숫자 들여쓰기 제거. 관련 명령: `$impeccable layout`, `$impeccable typeset`.
2. **P1 — 커트·경과 입력의 정보 묶음 부족.** `record-pages.tsx`와 `interface.css:1334`의 단일 흰색 폼에서 날짜·시술·부위·메모·사진이 연속. 입력 테두리는 있어도 의미상 그룹은 약함. 커트 정보(날짜/시술/부위), 당일 기록(메모/사진), 선택 정보(미용실/담당자/가격)를 소제목·일관된 간격·제한된 연한 배경으로 분리. 경과는 날짜/D+ 맥락과 변화 메모/사진을 구분. 모든 항목을 새 카드로 감싸 중첩하지 않음. 관련 명령: `$impeccable layout`, `$impeccable clarify`.
3. **P1 — 하단 행동 영역이 선택 입력의 발견을 방해하는 상태.** 390×844의 요청 작성에서 `.request-options summary` y758.8, 높이44, 행동 영역 y764~844. 해당 문구의 중심을 `elementFromPoint`로 검사하면 “내용 확인하기”가 잡힘. 스크롤 후 접근 가능하므로 입력 불가라고 해석하지 않음. B의 커트 폼 초안 상태에서는 겹침이 재현되지 않았음; 화면/상태를 구분. 요청 선택 입력과 주 버튼 사이 공간 및 sticky/fixed 배치를 재설계하고 실제 첫 화면에서 확인. 관련 명령: `$impeccable adapt`, `$impeccable harden`.
4. **P2 — 보조 행동과 안내의 시각적 규칙 불일치.** 작업 상단 나가기·제목 옆 돌아가기·폼 하단 나가기 반복. 기록 수정/경과 추가/디자이너 선택/도움 안내 등 보조 요소들이 비슷한 청록/회색 작은 글자로 표시. 주 행동은 채운 버튼, 부가 행동은 분명한 텍스트/외곽 버튼, 펼침은 동일한 행/화살표, 안내는 비인터랙티브 글로 역할 고정. 기록 목록과 상세도 하나의 기록 객체가 이어진다는 묶음 규칙 공유. 관련 명령: `$impeccable clarify`, `$impeccable polish`.

## 사용자 관점

처음 쓰는 사용자는 어느 정보를 한 묶음으로 작성하는지 읽으며 추론해야 함. 한 손으로 쓰는 사용자는 반복된 나가기와 첫 화면에서 가려지는 선택 입력을 발견하기 어려움. 키보드·보조 기술 사용자는 뒤로가기의 접근성 이름은 남아 있으나 시각 문구는 숨겨져 있으며, 실물 스크린리더 런타임은 미검증. 6개 부위 선택은 같은 종류의 선택이므로 무관한 여러 결정을 동시에 강요하는 상태와 구분.
