# AI 도우미 API 계약

2026-11-07 기준 계약입니다. 서버는 `backend`의 `ai` 패키지, 화면은 `frontend/src/ai-assist.tsx`가 이 문서를 따릅니다. DB는 쓰지 않습니다. 경로·필드·오류를 바꿀 때는 코드보다 이 문서를 먼저 고칩니다.

## 한눈에 보기

| 하는 일 | 요청 | 쓸 수 있는 사람 |
|---|---|---|
| AI 도우미를 쓸 수 있는지 | `GET /api/ai/status` | 로그인한 회원 |
| 상담 요청 글 다듬기 | `POST /api/ai/request-draft` | 로그인한 회원 |
| 고민에 맞는 디자이너 찾기(서버만 유지, 화면에서 안 씀) | `POST /api/ai/designer-match` | 로그인한 회원 |
| 내 기록을 보고 답하는 AI 상담 | `POST /api/ai/chat` | 로그인한 회원 |

## 공통 규칙

- 모델은 서버가 OpenAI 호환 `POST {SALU_AI_BASE_URL}/v1/chat/completions`로 부릅니다. Ollama와 OpenAI가 같은 형식이라 환경 값 `SALU_AI_BASE_URL`·`SALU_AI_MODEL`·`SALU_AI_API_KEY`·`SALU_AI_REASONING_EFFORT`(기본 `none`, OpenAI gpt-5 계열은 `minimal`, 비우면 보내지 않음)만 바꿉니다. 추론을 끄지 않으면 로컬 모델이 수십 초 걸립니다. 주소가 비어 있으면 AI 도우미가 꺼진 상태입니다.
- 모델 호출은 DB transaction 밖에서 합니다. 결과는 제안일 뿐 서버에 저장하지 않고, 사용자가 `적용`을 눌러야 입력 칸에 들어갑니다.
- 답의 흔들림을 줄이려고 `temperature`를 `SALU_AI_TEMPERATURE`(기본 0, 비우면 보내지 않음)로 고정합니다.
- 글 다듬기는 사용자가 이번 요청에 적은 글만 모델에 보냅니다. 디자이너 찾기와 AI 상담은 질문 글, 서버가 고른 공개 디자이너 프로필(이름·전문 분야·소개·매장), 서버가 고른 내 기록 몇 줄을 보냅니다(아래 `내 기록 고르기`). 서버는 이 자료를 `[고객 기록]`·`[디자이너 목록]`·`[질문]`처럼 이름표를 붙인 구역으로 나눠 넣고, 모델이 스스로 찾게 하지 않습니다. 회원 이름·이메일·사진·상담 내용은 보내지 않습니다.
- 회원당 1분에 10번까지입니다(서버 한 대의 메모리). 예시 체험과 로그인 전에는 화면에 나오지 않습니다.
- `POST`에는 CSRF 헤더가 필요합니다. 응답에는 `Cache-Control: no-store`가 붙습니다.

## 쓸 수 있는지

`GET /api/ai/status` → `{ "enabled": true }`. `false`면 화면은 AI 버튼을 숨깁니다.

## 상담 요청 글 다듬기

```json
POST /api/ai/request-draft
{ "text": "옆머리 뜨는거 어케 해요", "tone": "plain" }
```

`text`는 공백이 아닌 1~2,000자. `tone`은 말투로 `plain`(해요체, 기본·생략 가능)·`polite`(합니다체) 중 하나, 그 밖의 값은 400. 짧게 줄이는 말투는 qwen3:8b·nemotron 모두 길이를 줄이지 못해 두지 않음(2026-11-06 점검). 응답은 `{ "text": "옆머리가 자꾸 떠요. 손질하는 방법이 궁금해요.", "kept": false }`. 모델은 적힌 사실만 해요체로 짧게 고치고 새 사실·질문을 지어내지 않게 지시합니다. 커트 준비에서 채운 여러 줄 글은 줄 수·순서와 줄 앞 `옆머리(물어보기):` 같은 표시를 그대로 두고 내용만 고칩니다. 결과는 2,000자에서 자릅니다. 서버는 결과를 아래 규칙으로 검사하고, 하나라도 걸리면 결과를 버리고 원래 글을 그대로 돌려주며 `kept: true`로 알립니다.

- 원래 글이 여러 줄이면 줄 수와 줄 앞 표시(`…:`까지)가 같아야 함
- 원래 글에 없던 숫자가 생기면 안 됨(날짜·기간·가격을 지어냄)
- 원래 글(여러 줄이면 그 줄)에 묻는 말이 있었으면 다듬은 글에도 물음표나 `궁금`·`할지` 같은 묻는 말이 남아 있어야 함(질문을 빼고 사실만 남기면 뜻이 바뀜)
- 길이가 원래 글의 1.6배+30자를 넘으면 안 됨(내용을 덧붙임)

커트 준비 `상담 내용 적기`에서는 원하는 점·집에서 손질·추가 질문 칸을 `부위(원하는 변화): 내용` 한 줄씩 묶어 보내고, 받은 줄을 순서대로 칸에 되돌립니다(줄바꿈이 있는 칸은 보내지 않음). 묶은 글이 2,000자를 넘으면 화면이 보내지 않고 `AI는 2,000자까지 다듬을 수 있어요`로 알립니다. 화면은 지금 글과 다듬은 글을 위아래로 보여 주고 바뀐 단어를 굵게 표시합니다. `이 글로 바꾸기` 뒤에는 `다듬기 전 글로 되돌리기`가 나옵니다. 제안을 받은 뒤 요청 글을 고치면 옛 글 기준 제안은 숨깁니다. `kept`면 `AI가 고친 글이 원래 뜻과 달라져서 보여 드리지 않았어요`, 모델이 고칠 곳이 없다고 본 때는 `고칠 곳을 찾지 못했어요`라고 알립니다.

## 고민에 맞는 디자이너 찾기

```json
POST /api/ai/designer-match
{ "concern": "곱슬이라 단발이 자꾸 부해져요" }
```

2026-11-07부터 디자이너 찾기 화면은 이 API를 부르지 않고 정해진 시술 항목과 후기 점수로 추천합니다([개발 계약](development-contract.md) `공개 미용실·디자이너`). 시연 범위를 AI 상담 하나로 모으려고 바꾼 것이며, 서버 API와 테스트는 그대로 둡니다.

`concern`은 공백이 아닌 1~1,000자. 순서는 아래와 같습니다. 고르는 일은 코드가, 순서와 이유 문장만 모델이 합니다.

1. 서버가 계정에 저장된 내 기록에서 고민과 관련 있는 기록을 고릅니다(`내 기록 고르기`).
2. 서버가 공개 디자이너 프로필 최대 50명 중 고민·고민과 관련된 기록과 전문 분야·소개가 겹치는 사람을 최대 8명까지 먼저 고릅니다. 겹치는 사람이 없으면 50명 전체를 후보로 둡니다.
3. 모델은 후보 안에서 최대 3명과 근거 구절(`quote`, 전문 분야 하나나 소개 한 문장)만 냅니다. 내 기록은 순서를 정할 때만 참고합니다. 모델에는 ID 대신 목록 번호를 주고 서버가 번호를 ID로 되돌립니다. 모델이 이유 문장을 쓰지 않습니다(쓰게 하면 프로필에 없는 효과·받지 않은 시술을 지어냄, 2026-11-05 점검).
   - `quote`가 그 디자이너의 전문 분야·소개에 글자 그대로 있지 않으면 서버가 그 디자이너를 버립니다. 글자 그대로 있어도 고민 글과 겹치는 말(두 글자 묶음, 조사·흔한 말 제외)이 없으면 관계없는 디자이너로 보고 버립니다. 다만 고민과 관련된 기록의 커트를 맡았던 디자이너는 남깁니다. 화면은 `프로필에 적힌 말 “…”`로 보여 줍니다.
4. 모델에 보낸 기록 중 그 디자이너가 맡았던 커트가 있으면 서버가 기록 그대로 `history` 문장을 만듭니다. 없으면 `null`입니다. 커트 이름은 화면과 같이 `날짜 + 시술`(시술이 비면 `커트`)입니다. 커트에 연결된 디자이너 프로필이 있으면 프로필 ID로, 없으면(직접 적은 담당자) 이름으로 맞춥니다. 이름만 같은 다른 디자이너에게 붙지 않게 하기 위함입니다.

```json
{
  "items": [ { "designerId": "…", "name": "민준", "quote": "다운펌", "history": "9월 20일 투블럭 커트 담당 디자이너예요." } ],
  "basis": [ "9월 20일 투블럭 커트", "9월 27일 경과" ]
}
```

모델이 후보에 없는 번호를 내거나, 같은 디자이너를 두 번 내거나, 근거 구절이 프로필에 없으면 서버가 버립니다. 맞는 디자이너가 없으면 `items`는 빈 배열입니다. `basis`는 모델에 보낸 내 기록의 날짜·종류이며, 화면은 `내 기록에서 참고한 것`으로 보여 줍니다. 보낸 기록이 없으면 빈 배열입니다.

### 내 기록 고르기

- 계정에 저장된 개인 기록(`personal-storage.md`의 백업 항목) 중 최근에 바뀐 40개 항목에서 커트와 경과를 읽습니다. 기기에만 있고 계정에 저장되지 않은 기록은 쓰지 않습니다.
- 커트는 날짜·시술·부위·좋았던 점·미용실·디자이너 이름, 경과는 날짜·부위·불편한 점·손질·궁금한 점만 씁니다. 항목마다 120자에서 자릅니다.
- 먼저 고민 글과 글자가 겹치는 기록 중 많이 겹치는 것부터 최대 3개를 `관련 기록`으로 고릅니다.
- 남는 자리는 날짜가 최근인 기록으로 채워 모두 최대 5개를 보냅니다. 겹치는 기록이 없어도 최근 기록은 보냅니다.
- 줄은 화면과 같은 기록 이름(`9월 20일 투블럭 커트`, 경과는 `9월 29일 경과(9월 20일 커트 뒤)`)으로 시작해 모델이 날짜를 바꿔 말하지 않게 합니다. 모델에는 줄마다 `(질문과 관련)` 또는 `(최근 기록)`을 붙여, 관련 기록을 먼저 보게 합니다. 디자이너 후보를 좁힐 때와 담당 디자이너를 남길 때는 관련 기록만 씁니다(최근 기록이 관계없는 디자이너를 끌어올리지 않게).
- 기록을 읽지 못하면(백업 키 없음 등) 기록 없이 진행합니다.

## AI 상담

```json
POST /api/ai/chat
{ "message": "9월에 자른 옆머리가 또 뜨는데 집에서 어떻게 해요?", "history": [ { "role": "user", "text": "…" }, { "role": "assistant", "text": "…" } ] }
```

`message`는 공백이 아닌 1~500자. `history`는 이 화면에서 나눈 앞선 대화로 최대 6개(각 1~1,500자, `role`은 `user`·`assistant`)이고, 서버에 저장하지 않습니다. 화면이 탭에만 보관하며 `새 대화`를 누르면 비웁니다. 한 번에 한 질문씩 보내고 답을 기다리는 동안 입력을 잠급니다.

서버는 아래 순서로 처리합니다. SALU는 대화를 서버에 저장하지 않으므로 화면이 앞선 대화를 보내고 서버가 턴마다 기록을 다시 고릅니다.

1. 규칙으로 먼저 거름(모델 호출 없음, 횟수에 안 셈, 대화에 남기지 않음 `blocked: true`). 차례대로 보고 처음 걸린 사유로 `○○은 머리 손질 상담에서 다루지 않아요. (갈 화면 안내)`를 돌려줍니다.

| 사유 | 걸리는 말(정규식 요약) | 안내 |
|---|---|---|
| 주차 정보 | 주차·발렛 | 디자이너 상세의 매장 위치 |
| 영업시간 | 영업 시간·오픈 시간·몇 시에 열어·휴무 | 매장에 직접 확인 |
| 예약·결제 | 예약 취소·변경·확인·내역, 환불, 결제 취소 | 답변 전 보낸 상담에서 취소하면 환불 |
| 예약 방법 | 예약 방법·어떻게 예약·예약하려면 | 떠넘기지 않고 `SALU는 예약 대신 디자이너에게 상담을 보내요…`로 상담 신청 순서를 알려 줌 |
| 쿠폰·포인트 | 쿠폰·포인트·적립·할인 코드 | SALU에는 없음 |
| 의학적 판단 | 탈모 치료·약·병원, 두피 질환, 피부염, 알레르기, 부작용 | 전문의 상담 |
| 계정 | 회원 가입·탈퇴·비밀번호·로그인 | 내 계정 화면 |

2. `지난번 자른`·`내가 받았던`·`단골`·`내 기록`처럼 기록을 봐야만 답할 수 있는 질문인데 계정에 백업한 기록이 없으면 모델에 보내지 않고 `아직 계정에 백업한 커트 기록이 없어서…`로 답합니다(`blocked: true`).
3. 대화의 첫 질문이면 모델에 입력 필터 지시(`다룰 수 있는 것: 헤어 시술, 머리 고민·손질, 커트 기록, 디자이너, 상담`, 맞장구·이어 묻기는 Y)로 Y/N 한 글자만 묻습니다. N이면 `저는 머리 손질과 커트 상담만 도와드릴 수 있어요`로 답합니다. 판정이 실패하면 통과시킵니다.
4. 서버가 `내 기록 고르기`대로 기록 최대 5개, 질문·관련 기록과 겹치는 공개 디자이너 최대 5명을 고릅니다. `다음 커트 때는요?` 같은 이어 묻기도 같은 기록을 보도록, 관련을 셀 때는 이번 질문과 앞선 고객 질문을 함께 봅니다. 겹치는 디자이너가 없으면 디자이너 목록을 비웁니다.
5. 모델에는 지시문, 앞선 대화, 그리고 마지막 질문을 아래 모양으로 보냅니다.

```text
[고객 기록] 서버가 고객 계정에 저장된 기록에서 고름
- (질문과 관련) 9월 20일 투블럭 커트 | 시술: 투블럭 커트 | 부위: 옆머리 | 디자이너: 민준
- (최근 기록) 9월 29일 경과(9월 20일 커트 뒤) | 부위: 옆머리 | 불편한 점: 옆머리가 떠요
[디자이너 목록] SALU 공개 프로필
- 민준 | 전문 분야: 다운펌, 옆머리 | 소개: … | 매장: 바람 헤어 강남점
[질문]
9월에 자른 옆머리가 또 뜨는데 집에서 어떻게 해요?
```

지시문은 해요체 3~6문장, Markdown 금지, `[고객 기록]`·`[디자이너 목록]`에 없는 시술·날짜·제품·가격·효과를 지어내지 않고 기록이 없으면 일반 상담으로 답하기, 기록을 근거로 들 때 그 줄 맨 앞 이름(`9월 20일 투블럭 커트`·`10월 15일 경과`)을 그대로 쓰고 경과 내용을 커트 날짜로 말하지 않기, 방법·추천을 물으면 답을 먼저 주고 되묻기는 마지막에 하나만(증상만 말했을 때만 먼저 되묻기), 디자이너는 목록에 있는 이름만, 직접 봐야 아는 것은 디자이너 상담을 권하기, 전화·카카오톡·네이버 예약·인스타그램 DM 같은 바깥 연락 경로 안내하지 않기, 진단·약은 말하지 않기입니다.

6. 답에서 Markdown 기호(`**`·`#`·줄 앞 `-`·`*`)와 `(질문과 관련)`·`(최근 기록)` 표시를 지우고, `[고객 기록]` 같은 구역 이름·지시문을 말한 문장과 카카오·네이버·인스타·DM을 안내한 문장은 문장째 지운 뒤 1,200자에서 자릅니다. 남은 글이 없으면 `답을 정리하지 못했어요…`로 답합니다.
7. 답에 이름이 나온 디자이너만 목록과 대조해 `designers`로 돌려줍니다(최대 3명). 모델이 지어낸 이름은 목록에 없어 빠집니다. 화면은 `○○ 디자이너 프로필` 링크로 보여 줍니다.

```json
{ "answer": "9월 20일 투블럭 커트 기록을 보면…", "designers": [ { "designerId": "…", "name": "민준" } ], "basis": [ "9월 20일 투블럭 커트", "9월 29일 경과" ], "blocked": false }
```

`basis`는 모델에 보낸 기록 이름이고 화면은 `참고한 내 기록`으로 보여 줍니다. 답은 참고용이며 화면 위에 `AI 답변은 참고용이에요. 직접 봐야 아는 것은 디자이너에게 상담해 주세요.`를 둡니다. 1분 10번 제한은 다른 AI 기능과 함께 셉니다.
