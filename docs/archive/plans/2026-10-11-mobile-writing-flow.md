# 커트 준비 작성 흐름 개선

> 당시 계획·승인 범위·검증 근거를 보존한 기록. 현재 구현 상태는 [문서 안내](../../README.md)와 점검표 기준.

사용자가 기존 검토안의 기본 완성도 개선과 모바일 작성 구조를 모두 승인했다. 2026-10-11: “일단 진행해보고 완성되면 다시 파악함”.

## 구현 범위

- 기존 3단계 `자료 고르기 → 원하는 점 적기 → 내용 확인` 유지. 부위·원하는 변화·내용은 같은 화면에서 입력한다.
- 작성 화면의 지난 커트·자료 개수는 짧은 맥락으로 표시한다. 모바일에서는 자료 내용을 접고, PC에서는 옆에서 확인할 수 있다. 고른 경과·사진과 기록 문구 가져오기 기능을 보존한다.
- 핵심 입력은 카드 안의 중첩 카드 대신 간결한 입력 묶음으로 표시한다. 선택한 디자이너는 보조 맥락으로 표시한다.
- 손질 방법·추가 질문은 선택 입력으로 접는다. 값이 있는 초안을 다시 열면 펼친 상태로 시작하고, 사용자가 접어도 작성된 항목을 표시한다.
- 모바일에서는 입력·선택 컨트롤과 주 행동을 읽기 쉽게 배치한다. 메뉴·안전 영역에 버튼이 가리지 않게 한다. 모션 감소 설정과 키보드 탐색을 유지한다.
- 서버 저장 오류는 재시도 시작/완료에 맞춰 갱신한다. 기기 저장 오류를 서버 오류로 덮지 않고, 미전송 항목·충돌·저장 대기 초안이 있으면 서버 저장 완료로 표시하지 않는다.
- 보조 글자·플레이스홀더 대비를 높이고 안내·오류를 해요체로 통일한다. 미리보기의 목록 이동 버튼은 `준비 목록으로`로 표시한다.

## 보존할 계약

기기 우선 저장, 로그인 전 작성 내용 연결, 게스트/계정/예시 격리, 메뉴 이동 시 폼 유지, 선택 자료만 담기, 미리보기 스냅샷, 저장 실패 시 입력 보존을 유지한다. 서버 API·DB 구조·실제 상담 전송·등록 디자이너 목록은 변경하지 않는다.

## 검증 계획

기존 PC/모바일 화면 검증과 기기 저장 검증, 실제 Spring·salu_test 인증/백업 검증을 수행한다. 서버 재연결 시 변경 항목이 없는 경우, 업로드 대기와 충돌이 있는 경우, 기기 저장 실패를 구분해 확인한다. Playwright로 첫 화면 입력 노출·선택 정보 펼침/복원·자료 가져오기·내용 확인/목록 재진입을 검사한다. Browser 플러그인이 없어 프로젝트의 Playwright를 사용한다. 실제 모바일 OS 키보드는 별도 기기 확인이 필요하다.

## 구현과 검증 결과

승인한 범위 구현 완료. 기존 Impeccable 검토의 우선 문제 5개를 처리했다. [기존 검토](../../../.impeccable/critique/2026-10-11T11-26-54Z__frontend-src.md)는 당시 관찰과 점수 기록으로 보존하며, 이번 작업에서 전체 디자인 점수를 새로 매기지는 않았다.

- 모바일 390×844 예시 작성 화면에서 첫 내용 입력란은 y=565.84, 높이 112px. 하단 확인 영역은 y=696px로 입력란 전체가 먼저 보이고 서로 겹치지 않음. 버튼 높이 52px, 선택 컨트롤 높이 48px. 단일 항목의 중복 제목 제거, 여러 항목에는 순서와 삭제 동작 유지.
- 지난 커트 날짜·선택 자료 개수를 짧게 표시하고 선택한 경과·사진만 펼쳐 확인. PC에서는 옆에서 확인. 기록 문구 가져오기 후 해당 내용 입력란에 포커스 이동 확인.
- 손질 방법·추가 질문은 접어 시작. 작성 여부를 요약에 표시하고, 입력한 초안/준비본을 다시 열면 펼쳐 시작. 새로고침·메뉴 이동·미리보기 생성과 재진입 후 값 유지 확인.
- 390×500에서는 확인 버튼을 문서 흐름에 배치하고 포커스용 스크롤 여백 확보. 질문 입력란에서 Tab 이동한 확인 버튼의 하단 y=343.61, 하단 메뉴 시작 y=431로 가림 없음. 320×740에서는 긴 화면을 스크롤해 입력·확인 가능. 820×1000 중간 너비와 긴 입력에도 가로 넘침 없음.
- 기기 오류와 서버 오류를 구분. 서버 재시도 시작/완료에 맞춰 표시 갱신. 업로드 대기·충돌·저장 대기 초안이 남으면 서버 저장 완료로 표시하지 않음. 백업 화면도 저장소 변경을 구독하여 충돌과 복원 초안 표시 갱신.
- 사용자 안내/오류의 해요체 통일. 화면과 접근성 이름을 `부위 / 원하는 변화 / 원하는 내용`으로 맞춤. 목록 이동 버튼은 `준비 목록으로`. 백업 복원은 기존 자료 옆에 복사본을 추가한다는 실제 동작을 유지.

초기 실패는 새 문구를 아직 반영하지 않은 기대값과, 저장 상태가 없는 소개 홈에서의 검증 위치에 해당했다. 브라우저 QA는 예시 체험 종료와 내부 메뉴 이동을 구분하고 메뉴 전환 후 화면 준비를 기다리도록 정리했다. 실제로 발견한 하단 버튼 가림은 입력 간격과 짧은 화면/포커스 스크롤 규칙으로 수정했다.

임시 화면 증거: `/tmp/salu-writing-flow-{desktop,mobile,small}.png`, `/tmp/salu-writing-preview-{desktop,mobile,small}.png`, `/tmp/salu-writing-short-viewport-final.png`, `/tmp/salu-writing-flow-qa.json`. 기본 개발 화면 `http://127.0.0.1:5174`에 반영. 테스트 서버의 임시 계정·백업·키는 서버 종료 시 정리.

실물 휴대폰 키보드·Safari·스크린리더·실제 Google/네이버 동의는 이번 검증에 포함하지 않음. 상담 송수신·후기 작성·디자이너 관리·커뮤니티·네이티브 앱은 기존 후속 범위 유지.
