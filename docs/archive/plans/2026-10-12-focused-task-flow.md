# 한 작업에 집중하는 화면 흐름

> 당시 계획·승인 범위·검증 근거를 보존한 기록. 현재 구현 상태는 [문서 안내](../../README.md)와 점검표 기준.

2026-10-12 사용자 승인: 목업의 배치를 복사하는 대신, 한 작업을 끝내고 다음 단계와 결과를 명확히 보여 주는 흐름 구현.

## 구현

`참고할 커트 → 사진·메모·경과 선택 → 원하는 점 작성 → 저장 전 확인 → 저장 완료 → 보관한 내용`.

- 자료 선택·요청 작성·확인에서는 주 메뉴와 계정 버튼을 숨김. 기록·경과 입력에도 동일 적용. `나가기`는 초안을 보존하고, `작성 내용 지우기`만 확인 후 폐기. 원본 수정 초안을 폐기해도 저장된 원본은 유지.
- 나간 작업 화면을 유지해 사진 처리 중 이동해도 완료 가능. 저장 중 홈으로 나가면 홈을 유지하고, 기록 메뉴로 돌아왔을 때 저장 결과 확인. 작성 재개와 뒤로가기는 스크롤 복원.
- `/requests/review?draft=:id`는 저장 전 확인. 진입·자료 수정·요청 수정만으로 준비본이 생기지 않음. `준비 저장하기`가 성공해야 `/requests/complete/:id`로 이동. 실패 시 문장·선택 유지, 재시도 가능. 중복 탭과 같은 초안의 재저장으로 준비본 중복 생성 방지.
- 완료는 큰 체크와 짧은 결과 문구로 표시. 개인 영역은 기기 저장, 예시는 체험 안에서 보관한다는 실제 동작에 맞춘 문구. `/requests/previews/:id`는 보관한 내용이며 완료 체크·진행 단계를 반복하지 않음. 실제 상담 전송 기능은 추가하지 않음.
- 자료는 사진을 먼저 보여 주고, 사진이 없거나 불러오기에 실패하면 같은 크기의 상태 표시. 원본 커트 변경은 보조 펼침으로 배치. 전체 선택·개별 선택·전체 해제와 사진 확대 유지.
- 디자이너 소개와 상담 후기를 독립된 영역으로 구분. 소속 이력은 보조 정보. 가상 후기임을 명시.
- 날짜는 월·일을 읽기 쉬운 한국어로 표시. 입력은 연·월·일 전체 표시, 숫자·구분자·한국어 입력 지원. 현재 연도가 아닌 기록에는 연도도 표시. 달력 선택과 날짜 순서 검사 유지.
- 오류는 붉은 글자·아이콘·배경으로 항목 제목과 구분하고 첫 오류로 이동. 충돌은 황색 안내, 백업 결과는 성공/처리 중/실패를 구분. 소셜 로그인 목록 조회 실패는 재시도 안내.
- 화면 진입·선택·완료에 짧은 모션 적용. 이동 애니메이션은 본문에 한정해 고정 버튼의 위치 기준 보존. 모션 감소 설정에서는 이동과 체크 애니메이션 생략. 짧은 화면과 키보드 열린 상태에서는 행동 버튼을 문서 흐름에 배치.

## 보존 범위

인증 API·CSRF·세션, 서버 DB, IndexedDB·ZIP 형식과 ID, 선택 자료만 담는 불변 snapshot, 여러 초안/준비본, 원본 재선택, 기존 호환 URL 유지. 예시 체험과 개인/계정 자료 격리 유지. 이번 작업은 프론트 흐름 변경이며 실제 상담 송수신·후기 작성·등록 디자이너 관리 구현으로 해석하지 않음.

## 검증

Browser plugin 미제공으로 프로젝트 Playwright 사용. Impeccable와 한국어 UX 문구 기준 적용. 초기 화면 점검에서 발견한 고정 버튼의 애니메이션 가림, 날짜 포커스 시 입력 연결, 폐기 확인창 재진입, 사진 없는 상세의 중복 빈 상태를 수정한 뒤 최종 확인 1회 수행.

| 실제 계정 저장 | 격리 salu_test·Spring 8083, 5개 항목 통과. 전체 실행 4개와 나가기 후 로그아웃 경로 조정 뒤 재검증 1개. 로그인 전 사진·초안 연결, 자동 저장, 새 기기 복원, 계정 분리, 장애/충돌 복구 포함 |

신규 검증은 실제 IndexedDB를 읽어 확인 진입 때 저장본 0건·성공 후 1건 확인. 저장 실패를 주입해 완료 화면으로 이동하지 않으며 재시도에 성공하는지 확인. 사진 없음/이미지 실패, 날짜 표시·편집과 오류 색상 구분, 이동 중 사진 처리·저장 완료도 검증.

화면 증거: `/tmp/salu-focused-final-{profile,materials,write,review,complete,detail}-{너비}-{높이}.png`, 측정 `/tmp/salu-focused-final-qa.json`. 모바일 자료·프로필·확인·완료 캡처를 직접 확인.

실물 휴대폰 OS 키보드·Safari·스크린리더·Google/네이버 실제 동의는 미검증. 로컬 소스 변경이며 NAS 이미지 재빌드·배포와 Git 원격 반영은 이번 실행에 포함하지 않음.


## HTTP 기록 저장 오류 보완

같은 날 사용자 제보: 저장 시 `확인이 필요해요 / 기록을 확인하고 다시 시도해 주세요` 표시. 일반 HTTP 호스트에서 실제 Chromium 재현: `isSecureContext=false`, `crypto.randomUUID` 미제공으로 기록 ID 생성 실패. 로컬호스트·HTTPS 검증만으로 발견하지 못했던 조건.

ID 생성을 공통 함수로 모으고 `randomUUID`가 없을 때도 제공되는 `crypto.getRandomValues`로 UUID v4 생성. 기록·경과·사진·준비·백업 복원·동기화 변경 ID·백그라운드 이동 모두 같은 함수 사용. 기존 ID와 저장 형식 유지. 예상 밖 기록/경과 저장 실패 안내는 저장 실패와 입력 보존을 명시. 원문 예외는 화면에 노출하지 않음.

일반 HTTP 주소 `http://salu.test:5186`를 로컬 서버로 매핑해 수정 전 오류와 수정 후 실제 저장·상세 이동·오류 없음 확인. 사용자가 접속한 주소는 아직 확인 전이므로 사용자 환경의 동일 원인 여부는 구분. NAS 배포는 별도.

보완 검증: 기록/사진/경과/준비/이동/백업 PC·모바일 28개 항목 통과(전체 26개 + 신규 테스트 입력란 이름 정정 후 2개 재검증). 실제 Spring·salu_test 계정 저장 5개 통과. build·format:check·diff --check 통과. 테스트 서버 종료로 임시 계정·백업 fixture 정리.
