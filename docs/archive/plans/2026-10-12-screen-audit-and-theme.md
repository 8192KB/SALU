# 화면 구분·테마·전체 검증

> 당시 계획·승인 범위·검증 근거를 보존한 기록. 현재 구현 상태는 [문서 안내](../../README.md)와 점검표 기준.

## 확정 범위

흰 화면을 기본으로 유지하되 배경은 `#F7F9F8`, 입력·본문 표면은 흰색, 참고 자료와 선택 정보는 낮은 채도의 별도 표면 사용. 기기 설정을 기본으로 따르는 밝은/어두운 화면 추가. 헤더의 화면 설정은 작성·로그인·예시 상태에서 모두 접근 가능.

커트 정보·당일 기록·선택 정보, 관찰 시점·변화 기록·추가 정보, 참고할 지난 기록·이번 요청을 의미별로 구분. 같은 항목을 묶고 다른 기능은 제목·표면·간격으로 구분. 뒤로가기 문구를 별도 행에 배치하고 모바일에서도 문구 유지. 저장 전 확인·저장 성공·저장한 상세의 차이 보존.

기존 기기 저장·사진·초안·ZIP·로그인 후 자동 암호화 백업 계약 유지. 실제 상담 전송·커뮤니티·가입 디자이너 도메인 API·네이티브 앱·실제 Google/네이버 제공자 동의 검증은 후속 범위. NAS 배포·Git 업로드는 이번 변경에 포함하지 않음.

## 저장·테마 계약

개인 기록은 기존 IndexedDB, 계정 인증은 서버 세션 유지. localStorage에는 비민감한 테마 선택 `salu.theme`의 `system`, `light`, `dark`만 허용. 저장 제한 시 현재 세션에만 적용. OS 밝기 변경은 system에서 즉시 반영하고 직접 선택한 모드는 유지. 로그인·예시 전환으로 테마와 입력을 초기화하지 않음.

초기 HTML에서 유효한 선택만 읽어 색상 모드를 설정하고 CSS의 의미별 색상 변수로 입력창·달력·사진창·내비게이션·오류·경고까지 연결. reduced motion 사용자는 기존 완료·접기 애니메이션 제한 유지.

주요 크기 390×844, 820×1180, 1180×820, 1440×1000에서 두 테마 확인. 추가 320×740·390×500·701×900와 200% 확대에 해당하는 720×500 CSS viewport·DPR 2 확인. 측정 범위 내 가로 넘침·본문 대비 미달·44px 미만 링크/버튼/summary·pageerror·예상 밖 API 요청 0. 대비 측정은 DOM의 표시되는 본문, 조작 영역 측정은 링크·버튼·summary 대상으로 수행하며 완전한 접근성 인증을 주장하지 않음.

모바일의 첫 화면·전체 화면과 핵심 전체 내용을 검토. 태블릿 가로·세로와 PC는 읽기 전용 Luna 검토로 교차 확인. 같은 항목의 묶음, 이전 자료/새 요청, 소개/후기, 저장 전/성공/저장 상세, 뒤로가기 독립 행 확인. 전체 사진에서 고정 내비게이션이 중간에 보이는 것은 fullPage 캡처 방식의 결과이며, 끝 항목의 스크롤 접근과 짧은 화면/키보드 이동은 별도 확인.

처음 검증에서 접기 제목 변경에 따른 locator 실패와, 저장·메뉴 전환 전에 다음 클릭을 시도하는 타이밍 실패 확인. 최종 검증은 실제 성공 화면·목록 제목을 기다리며 기존 선택·저장·스냅샷 assertions를 유지. 임의 sleep·반복 retry로 통과시키지 않음.

추가로 찾아 고친 동작:

- 연결한 소셜 계정 조회 실패를 숨기던 경로 제거. 제공자 목록과 연결 상태가 둘 다 확인되기 전에 연결 버튼 비노출, 실패 안내·다시 조회 제공. 실제 로그인 계정과 합성 제공자 응답을 사용한 인증 회귀로 대기·실패·복구 확인. 실제 제공자 동의 완료와 구분.
- 로그인 서버 장애 중 로그인 시도 후 연결 경고와 제출 오류가 중복되지 않게 정리. 상태 재확인 후 이전 제출 오류 제거.
- 복원한 작성 초안의 날짜도 한국어 월·일로 표시. 미완성 날짜는 ‘날짜 미정’. 이어 작성 버튼은 해당 초안을 선택하고 작성 화면으로 이동. 현재 초안은 복원 목록에 보존. 실제 ZIP 복원·이동·재접속 검증.
- 변경 충돌이 자동 저장 진행 중으로 계속 표시되던 상태를 ‘변경 확인 필요’로 분리. 복구 전 성공 표시 금지, 기기 저장 실패 우선순위 유지. 실제 두 브라우저 충돌·복구 검증 통과. 저장 문서·API·암호화 형식 변경 없음.

실제 인증·백업은 salu_test 임시 계정만 사용하고 trace/video/screenshot 비활성화. 검증용 Spring·프론트 종료 및 fixture 정리. 정상 개발 Spring 8081과 기존 프론트 5174는 유지. 개발 주소 health 200·guest me 401·providers 200/빈 목록 확인. 실제 Google/네이버 제공자 설정은 아직 없음.

Browser 플러그인이 이 세션에 없어 일반 Playwright Chromium 사용. 태블릿 크기·확대는 브라우저 에뮬레이션이며 실제 태블릿 OS 키보드·Safari·스크린리더 검증과 구분. 실제 소셜 제공자 설정 없이 표시·오류·연결 상태는 합성 응답으로 검토. 실물 기기·제공자 동의는 후속 확인 범위.

사진 목록: `/tmp/salu-ui-audit-report-20261012/index.html`, 상태별 측정: 같은 폴더의 `matrix.json`. 사진은 공개 예시·합성 계정만 포함. 임시 파일이며 아래 도구로 재생성 가능. Git 업로드·NAS 배포는 실행하지 않음.

## 재현 도구

```bash
cd frontend
node scripts/audit-screens.mjs
node scripts/audit-network.mjs
SALU_AUDIT_SET=extras SALU_CAPTURE_OUTPUT=/tmp/salu-ui-audit-extras-20261012 node scripts/audit-screens.mjs
node scripts/audit-network.mjs
SALU_AUDIT_SET=edge SALU_CAPTURE_OUTPUT=/tmp/salu-ui-audit-edge-20261012 node scripts/audit-screens.mjs
npm run build
npm run format:check
npm run test:e2e -- --workers=2 --timeout=30000
```
