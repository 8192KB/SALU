# 현재 인증·기록·요청 준비 검토

> 당시 계획·승인 범위·검증 근거를 보존한 기록. 현재 구현 상태는 [문서 안내](../../README.md)와 점검표 기준.

이 검토는 소개 홈·예시 체험 분리 전 상태의 기록. 이후 화면과 인증 검증은 [현재 화면 계획](../../prototype-plan.md)과 [로그인 검증](../../login.md) 참고.


상태: 기존 구현 검토 완료 · 보완 항목 미수정
검토일: 2026-10-10
대상 버전: frontend 0.1.0 · backend 0.1.0-SNAPSHOT
적용 방식: `feature-docs` DOCUMENT 기준으로 코드·계약·검증 대조

## 결론

기존에 선언한 완료 범위에서 이번 검증의 회귀 실패 없음. 예시 화면과 실제 인증의 경계, 선택한 자료의 불변 미리보기, 명시적 디자이너 연결은 코드와 기존 테스트에 일치. 보안 문제가 전혀 없다는 판정이나 후속 업무 기능의 완료 판정은 아님.

추가 확인에서 시간대에 따른 날짜 불일치와 인증 성공 뒤 후속 조회로 인한 화면 지연 발견. 기록 없는 첫 이용·첨부 없는 상담 등은 현재 계약대로 제한되어 있으나 후속 개발 전에 재검토할 제품 결정. 이번 작업은 검토·계획 초안 작성이며 기능 코드 수정 없음.

후속 사용자 제안의 로그인 없는 기기 저장·수동 백업·선택 계정 연결은 [개인 기록과 7주차 검토안](../plans/2026-10-10-local-records-and-week7-review.md)에 정리. 이 검토의 통과 결과는 새 저장·복원 기능의 검증 결과가 아님.

## 검토 범위

| 묶음 | 구현·검토한 내용 | 현재 경계 |
|---|---|---|
| 인증 | Spring 세션·ACTIVE 상태·CSRF·로그인/me/logout·React 계정 상태 | 로컬 계정. 가입·계정 복구·디자이너 등록 미구현 |
| 기록 | 커트·경과 생성/수정, 입력·날짜 검사, 사진 확인·확대, 초안 보존 | 메모리 예시. 새로고침/계정 전환 시 초기화 |
| 요청 준비 | 개인 준비, 명시적 자료 선택, 여러 초안, 디자이너용 복사, 과거 미리보기 보존 | 전송 전 자료. 서버 저장·실제 답변 없음 |
| 공통 기반 | 오류 JSON·인증 경계·검증 전용 트랜잭션 Service | 실제 기록·사진·상담 Service의 검증을 대신하지 않음 |

## 확인된 보완 항목

### R01 · P2 · ‘오늘’의 기준이 브라우저 시간대에 의존

- 근거: [dates.ts](../../../frontend/src/prototype/dates.ts)의 `today()`가 브라우저의 `getFullYear/getMonth/getDate` 사용
- 재현: 같은 순간 `2026-10-10T00:30:00Z`, 브라우저 `America/Los_Angeles`, 새 커트 날짜와 입력 상한 모두 `2026-10-09`. 서울 날짜는 `2026-10-10`
- 영향: 한국 기준 당일 기록을 하루 전으로 기본 입력하거나 당일 날짜를 미래로 판단. 서울보다 날짜가 앞선 지역에서는 한국 기준 미래 날짜를 허용할 가능성
- 판정: 현재 예시의 날짜 구현과 후속 계약의 `Asia/Seoul` 기준 사이 불일치. 서울 시간대로만 실행한 기존 테스트에서 드러나지 않는 항목
- 제안: 업무 날짜 기준을 확정하고 프론트·서버에 일치 적용. 자정 경계·다른 시간대 확인을 기록 연결의 완료 기준에 추가
- 상태: 재현 완료, 수정 전

### R02 · P2 · 인증 성공 화면이 후속 CSRF 조회를 기다림

- 근거: [auth/api.ts](../../../frontend/src/auth/api.ts)의 로그인·로그아웃이 성공 응답을 받은 뒤 `await csrfHeaders().catch(() => {})` 실행
- 재현: 비밀값 없는 브라우저 응답 재현에서 로그인 200을 먼저 반환하고 이후 CSRF 조회만 3.5초 지연. 성공 1초 뒤에도 `/login`에서 `로그인 중` 표시, 약 3.9초 뒤 계정 표시
- 영향: 이미 성공한 인증의 표시와 예시 자료 초기화가 후속 요청 시간만큼 늦어짐. 현재 요청 timeout은 8초이므로 후속 요청 지연도 기다림
- 판정: 인증 실패·세션 보안 우회가 아니라 성공 피드백 지연. 로그인에서 재현했고 로그아웃도 같은 대기 구조는 코드로 확인
- 제안: 성공 응답의 확정과 후속 토큰 준비를 분리하되, 토큰 갱신·다음 변경 요청 전 CSRF 조회·계정 전환 정리 계약 유지. 늦은 후속 응답이 새 계정 상태를 바꾸지 않는지 함께 검증
- 상태: 로그인 지연 재현 완료, 수정 전

## 구현 오류와 구분할 제품 결정

| ID | 현재 코드·계약 | 검토할 이유 | 확정할 내용 |
|---|---|---|---|
| D01 | 개인 준비에도 기준 커트 필요. 커트가 없으면 프로필의 상담 자료 선택 버튼 비활성 | 가상 기록이 항상 있는 화면에서는 신규 사용자의 빈 상태가 가려짐 | 첫 실제 기록 작성 후 준비 / 과거 기록 간단 입력 / 기록 없는 질문 시작 중 채택 |
| D02 | 디자이너용 준비에는 메모·경과·사진 중 최소 하나 필요 | 좋았던 점 없는 텍스트 커트만 만든 사용자는 질문을 적어도 상담용 준비 불가 | 첨부 필수 유지 / 요청 문장만으로 허용 / 개인 준비까지만 허용 |

| D04 | 원본 수정 뒤 미리보기 보존, 사진 삭제·철회·탈퇴 정책은 미정 | 불변 자료와 이후 접근 철회가 동시에 필요 | 텍스트 보존과 사진 접근 종료·보존 범위를 구분하여 확정 |
| D05 | 고객 화면은 있지만 실제 디자이너 수신·답변·거절 흐름은 미구현 | 보내는 쪽만 완성하면 실제 왕복 상담의 가치·운영 부담 확인 불가 | 상대의 수신함·답변·보류/거절·재문의 정책과 시연 조건 |
| D06 | 현재 계약은 답변 받은 고객의 상담 후기 제안 | 상담 답변이 실제 시술 품질·방문 증거는 아님 | 후기 대상·작성 자격·중복·수정/삭제·소속 변경 표시 |

이 표의 제한은 기존 `prototype-plan.md`에 명시된 의도한 동작. 변경을 승인받은 요구사항으로 취급하지 않음. 상세 대안·진입 조건은 [개발계획 검토 초안](../plans/2026-10-10-development-plan-review.md)에 연결.

## 유지할 설계와 검증 근거

- 요청 `role/memberId`로 권한 부여하지 않고 세션 principal 사용. ACTIVE 계정 재확인, CSRF를 포함한 변경 요청 보호 유지
- 401과 서버 장애 분리. 장애만으로 예시 초안 삭제하지 않으며 확인된 회원 변경·로그인·로그아웃에서 예시 repository 교체
- 담당자 이름과 디자이너 프로필 ID 구분. 현재 소속과 기록 당시 매장명 구분
- 새 준비·개인 준비의 대상별 복사·내용 수정 시 기존 미리보기 보존. 최신 원본으로 전환은 명시적 조작
- 자료 미선택·날짜 역전·손상 이미지·decode 중 조작을 막고 실패 입력 유지
- Security 오류와 MVC 오류의 JSON 계약 중앙화. 실제 다중 변경 검증은 테스트 전용 Service·DB 사용

## 이번 실행 결과

| 확인 | 결과 | 실제 확인 범위 |
|---|---|---|
| `npm run build` | 통과 | TypeScript·Vite 빌드 |
| `npm run format:check` | 통과 | 기존 소스·테스트 형식 |
| `npm run test:e2e -- --workers=2 --output=/tmp/salu-review-e2e` | 44개 통과, skip 없음 | PC 22 + 모바일 22, 서버 없는 예시 화면 |
| `npm run test:auth -- --output=/tmp/salu-review-auth` | 9개 통과, skip 없음 | 실제 Spring8081·MySQL3307 인증. 장애·CSRF 일부는 브라우저 응답 재현 |
| `./scripts/verify-backend.sh` | 21개 통과, skip 없음, BUILD SUCCESS | salu_test 전용 fixture, 인증·공통 오류·실제 트랜잭션 커밋/롤백 |
| `python scripts/verify-api.py` | 통과 | 현재 실행 서버의 health·세션 cookie·CSRF·401/403 JSON |
| 추가 브라우저 검토 | R01/R02 재현, pageerror 없음 | 390×844, 시각·응답 지연 재현. 사용자 비밀번호 사용 없음 |

Browser plugin 미제공으로 기존 Playwright 사용. 최초 sandbox 실행은 로컬 socket 제한으로 E2E 서버가 시작되지 않아 실행 권한 확장 후 재실행. 이를 제품 실패로 계산하지 않음.

일시 증거: `/tmp/salu-review-backend.log`, `/tmp/salu-review-date-mobile.png`, `/tmp/salu-review-login-pending.png`. `/tmp` 결과는 영구 증거가 아니며 실제 계정 비밀번호·token을 문서·캡처에 넣지 않음.

## 검증의 한계

실제 DB 중단/복구 스크립트는 이번에 실행하지 않음. 기존 검증 이력은 [login.md](../../login.md) 유지. 물리 휴대폰·Safari·가상 키보드, 다중 서버·실제 운영 배포, 외부 사용자 사용성은 이번 검토 범위 밖.

기록 DB·사진 서버 업로드·상담 왕복·후기·공개 사례는 아직 미구현. 인증/화면 테스트 통과를 이 기능의 소유권·참여자·중복/동시성 검증으로 확대하지 않음. 초안에 있는 후속 수용 기준은 실행 결과가 아님.
