## 현재 읽을 방향

가장 최근의 발표 방향은 2026-10-07 `6주차_캡스톤발표.pptx`입니다. `수정용/SALU_6주차_최종본.pptx`와 SHA-256이 같고, 두 파일의 수정 시각·크기도 같습니다. 12개 슬라이드의 XML을 직접 확인했습니다. 기존 `README.md`와 10-06 `6주차_발표정리.md`가 10-04의 `6주차_발표_수정본_3.pptx`를 검토본으로 가리키는 내용은 최신 파일보다 오래됐습니다.

이 방향을 선택한 일과 강한 차별화가 증명된 일은 구분해야 합니다. 공개 자료 조사와 10-03의 경쟁 검토는 개인 기록·상담·사진 문의·프로필·후기가 이미 여러 서비스에 존재함을 확인했습니다. “기능 조합이 시장에 없다”, “이용자 편익이 확인됐다”, “SALU가 더 낫다”는 결론은 없습니다. 이는 현재 개발 방향을 설명하지 못하게 하는 판정이 아니라, 발표와 이후 검증에서 지켜야 할 주장 범위입니다.

## 통합 노트에 넣을 내용

1. **현재 방향:** 커트·경과 기록 → 자료 선택 → 디자이너 선택 및 1:1 상담 → 개인 프로필 후기. 예약·결제·AI 제외, 커뮤니티는 후순위.
2. **결정 연표:** 2–3주 예약 플랫폼 → 4주 기록/상담 카드로 전환 → 5주 사용 흐름과 선택 공유 구체화 → 6주 피드백을 받아 디자이너 답변·후기 연결.
3. **왜 이 흐름인가:** 기능 자체의 독자성이 아니라 과거 경험을 골라 상담에 연결하려는 개발 방향. 실제 편익은 아직 확인 과제로 표시.
4. **벤치마킹:** 각 서비스의 기록 주체·상담/대화·후기 연결을 한 표로 요약하고 공식 링크, 날짜, 확인 한계를 붙임. Miloq는 과거 반례 링크로 남기되 최종 핵심 비교 표에서 제외했던 이유도 씀.
5. **현재 무엇이 실제로 동작하는가:** SALU 클릭형 초기 화면과 인증 기반을 분리하고, 가상 메모리 데이터·실제 로그인·서버 DB·1:1 상담·후기 상태를 각각 구분.
6. **검증/남은 결정:** 같은 정보 기준의 사진·메모 대비 준비 시간·누락·입력 부담; 디자이너 응답; 후기 자격과 유형; 소속 검증. 계획과 결과를 별도 표기.

중복된 전문이나 후보별 보고서 본문을 현재 설명에 복제하지 말고 원문에 연결하세요. 오래된 발표와 보류된 후보는 “당시 안”으로 명시해 남기고, 삭제하거나 최신 방향에 섞지 않는 것이 안전합니다.

### 개인 디자이너 후기와 이직

- [Fresha 리뷰 도움말](https://www.fresha.com/help-center/knowledge-base/personal-account/35-respond-to-your-personal-reviews)은 다른 작업 공간에서 받은 리뷰의 개인 계정 조회와 현재 작업 공간에서 답변하는 범위를 구분합니다. 같은 고객 공개 프로필 주소에 모든 후기가 자동 승계된다는 증거로 쓰지 않습니다.
- 네이버는 [업체 관리](https://help.naver.com/service/30026/bookmark/20492?lang=ko&osType=COMMONOS)와 [예약 리뷰 이관](https://help.naver.com/service/30026/contents/20718?lang=ko&osType=COMMONOS)를 안내하지만 이를 디자이너 개인 후기의 이직 이전으로 해석하지 않습니다.
- [MY플레이스 리뷰 안내](https://help.naver.com/service/19485/contents/10471?osType=MOBILE)는 고객 본인이 작성한 리뷰 모음이며 디자이너 평판 프로필과 다릅니다.
- [카카오헤어샵 2016 공식 소개](https://www.kakaocorp.com/page/detail/8084)는 디자이너 프로필 노출의 선행 사례입니다. 현재 서비스 지속 여부를 확증하지 않습니다.
- SALU 계획: 디자이너 개인 ID와 현 소속을 분리하는 방향. 후기 작성 자격, 상담 후기/실제 시술 후기 구분, 소속 확인, 공개 프로필의 이직 연속성은 미결정입니다.

### 10-03 후보 조사에서 보존할 반례와 판정

10-03 재조사는 45개 앱이 아니라 기능 주장·후보를 검토했습니다. HairLogX의 집 손질 사진 비교, ECILA의 손질 영상 전달, Beauta의 문제 접수, KIREIDOT의 이력·대화, Trichue의 집에서의 경과·다음 요청, Carte의 상담 카드 재사용 등으로 단일 기능 신규성을 제한했습니다. KIREIDOT과 Trichue 기능은 앱을 직접 실행한 결과가 아니라 회사·앱 스토어 공개 설명과 게시 화면 범위로 기록되었습니다.
