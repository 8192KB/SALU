# 이용 의견 API 계약

2026-11-17 기준 구현된 계약입니다. 써 보다 불편했던 점·궁금한 점을 운영자에게만 보내는 기능입니다. 커뮤니티와 따로 두며, 다른 회원은 볼 수 없습니다. 서버는 `backend`의 `feedback` 패키지와 Flyway `V17__member_feedback.sql`이 이 문서를 따릅니다. 화면은 `frontend/src/feedback-api.ts`·`feedback-pages.tsx`가 따르고, 더보기의 `이용 의견`(보내기)과 관리자 묶음의 `받은 이용 의견`(읽기)에서 들어갑니다([화면 흐름](screen-flow.md)).

## 한눈에 보기

| 하는 일 | 요청 | 쓸 수 있는 사람 |
|---|---|---|
| 의견 보내기 | `POST /api/feedback` | 누구나(로그인하지 않아도 됨) |
| 받은 의견 목록 | `GET /api/admin/feedback` | 관리자 |

## 공통 규칙

- 보내기에는 CSRF만 넣습니다(로그인 전에도 `GET /api/csrf`로 받음). 개인 기록과 관계없어 `X-SALU-Storage-Context`는 넣지 않습니다.
- 보낸 회원도 자기 의견을 다시 볼 수 없고, 답·댓글·알림은 없습니다. 고치기·지우기도 없습니다.
- 로그인했으면 보낸 회원을 함께 저장하고, 로그인하지 않았으면 보낸 사람 없이 저장합니다. 이용이 제한된 회원도 보낼 수 있습니다.
- 응답에는 `Cache-Control: no-store`가 붙고, 오류는 `{ "code", "message" }`입니다.
- 관리자 역할은 [커뮤니티 API](community-api.md) 4장과 같이 DB에서만 정합니다. 관리자가 아니면 `403 ACCESS_DENIED`입니다.

## 1. 보내기

본문은 `{ "requestKey": "<UUID>", "content": "사진을 고른 뒤 저장이 안 돼요" }`입니다.

| 필드 | 뜻 |
|---|---|
| `requestKey` | 화면이 정한 UUID. 같은 사람(같은 회원, 또는 둘 다 로그인 전)이 같은 키로 다시 보내면 새로 만들지 않음 |
| `content` | 앞뒤 공백을 뺀 1~2,000자 |

| 결과 | 응답 |
|---|---|
| 새로 저장 | `201`, `{ "id": 12, "createdAt": "…" }` |
| 같은 키·같은 내용을 다시 보냄 | `200`, 처음 저장한 것 |
| 같은 키인데 내용이나 보낸 사람이 다름 | `409 CONFLICT` |
| 키가 UUID가 아니거나 내용이 비었거나 너무 김 | `400 INVALID_REQUEST` |

## 2. 관리자 목록

최근 받은 순서로 100개까지 돌려줍니다.

```json
[
  {
    "id": 12,
    "memberId": 3,
    "authorName": "하늘",
    "content": "사진을 고른 뒤 저장이 안 돼요",
    "createdAt": "2026-11-17T09:12:45.123Z"
  }
]
```

| 필드 | 뜻 |
|---|---|
| `memberId`, `authorName` | 보낸 회원의 ID와 지금 이름. 이메일은 넣지 않음. 로그인하지 않고 보냈으면 둘 다 `null` |
