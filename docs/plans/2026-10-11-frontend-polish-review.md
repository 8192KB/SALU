`WHOLE` 값은 기존 파일·서버 백업 호환을 위해 유지. 폼에서 기존 `WHOLE` 기록도 모든 부위가 선택된 상태로 표시. 전체 선택 저장은 `WHOLE`과 다섯 부위를 포함하고, 개별 해제 시 `WHOLE` 제거. 목록에는 중복된 여섯 태그 대신 ‘전체’ 하나 표시. 기록/경과의 전체 메모를 요청으로 가져올 때 요청 부위도 ‘전체’ 사용.

가격은 브라우저 기본 숫자 입력의 1,000원 격자 사용. 예: 25,000 → 24,000. 25,300원처럼 격자 밖 값에서 화살표를 누르면 인접한 천 원 금액으로 맞춰짐. 직접 입력의 백 원 단위를 자동 반올림하거나 저장 오류로 처리하지 않음.

프로필의 중요 정보는 이름·현재 매장·상담 분야·짧은 소개·상담 준비 행동. 이전 소속·후기 상세는 펼쳐 확인. ‘소속이 바뀌어도 같은 프로필’ 같은 설계 설명은 화면에서 제거하고 개발 계약에 보존. 실제 메시지 전송 미구현 상태는 예시 디자이너의 상담 시작 영역에 한 번 안내. 전송 버튼이나 전송 완료 표현 없음.

## 커트 준비에서 남은 혼란과 다음 방향

기본 흐름은 지난 커트 선택 → 참고 자료 선택 → 다음 커트에서 원하는 점 작성 → 정리한 내용 보관. 지난 커트를 선택했다는 사실과 새로 원하는 스타일을 적는 작업을 각 화면에서 분명히 구분. 작성 중 메뉴를 옮겨도 같은 화면으로 복귀하는 기존 동작 유지.

- 현재 메뉴·제목·요청 작성·준비본·미리보기 등 이름이 여러 개라 같은 작업인지 배워야 함. 이후 대표 이름은 ‘커트 준비’, 단계 행동은 ‘고르기·적기·확인’으로 통일하는 방향.
- 휴대폰의 요청 작성 화면에는 참고 자료, 요청 카드, 손질, 질문, 아래의 버튼이 함께 존재. 주 행동을 휴대폰 하단의 한 버튼으로 유지하는 개선 후보. 키보드·하단 메뉴·첨부 선택 바가 겹치지 않는 규칙 필요.
- 자료 재선택과 내용 수정은 보조 행동. 원본 기록 보기·소속 이력·후기·백업 설명은 관련 상세/메뉴 안에서 확인하는 방향.
- 이전 커트와 준비 완료 화면에서 현재 고른 커트의 날짜·시술을 간결하게 표시. 각 단계에 여러 개의 제목·설명 카드가 쌓이지 않게 정리.

사용자가 ‘등록된 디자이너 선택’과 ‘이전 기록의 담당자 다시 선택’ 모두 필요하다고 확인. 이전 담당자 재사용은 이번에 구현. 이름·매장만 복사하고 실제 프로필로 자동 연결하지 않음. 직접 입력으로 전환해도 채운 내용을 유지하고 수정 가능. 개인/계정/예시 영역의 현재 기록에서만 후보를 만들며 다른 영역의 기록 조회 없음.

선택칸은 이전 담당자와 프로필을 그룹으로 구분. 현재 예시에서는 가상 프로필 그룹도 선택 가능하지만, 개인 영역에는 실제 프로필 데이터가 없어 이전 담당자 재사용만 제공. 실제 등록 디자이너 그룹을 제공하려면 후속 공개 목록/조회 API·프로필 등록/관리·유효한 ID 연결과 저장 계약을 함께 구현해야 함. 개인 백업의 `designers`는 현재 빈 배열 계약이므로 API 결과를 임의로 백업에 넣지 않음.

다음 구현 추천: 실제 디자이너 프로필 목록·선택 → 상담 요청 전송/디자이너 답변/이력 → 후기 작성. 커뮤니티는 PPT의 후속 순서 유지. 실제 프로필 대신 가상 데이터를 개인 영역에 넣지 않음.

## 앱 느낌과 스킬 조사

SALU는 청록색·코럴 포인트·커트 사진/날짜 중심의 정체성 유지. 앱 느낌의 다음 개선 방향은 짧은 화면 제목, 명확한 주 행동 한 개, 하단 메뉴와 뒤로 가기, 입력/스크롤 유지, 필요할 때 펼치는 보조 정보, 터치 영역과 키보드 대응. 앱 패키징은 기존 React를 기반으로 검토할 수 있지만 네이티브 저장·파일 공유·카메라·오프라인 최초 실행은 별도 검증 대상.

세 방향의 차이: 현재 웹에 조작/문구만 개선하면 빠르지만 정보 구조는 그대로. 모바일 앱 흐름으로 페이지 구조를 정리하면 현재 React를 유지하며 접근성과 발표 시연을 개선. 네이티브 앱을 바로 시작하면 패키징·기기 기능 검증 범위가 커짐. 현재 추천은 모바일 페이지 구조 개선과 실제 디자이너/상담 기능 연결을 먼저 진행하는 방향. 전면 재설계나 앱 제작 완료로 기록하지 않음.
