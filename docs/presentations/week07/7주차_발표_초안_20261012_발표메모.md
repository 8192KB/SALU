## 이번 발표 범위

실제 [6주차 발표](</home/chuwe/Documents/Nextcloud Files/학교/4학년/캡스톤/6주차_캡스톤발표.pptx>) 12장의 예고: 커트·경과 저장·조회, 같은 커트에 경과 추가, React 입력·목록 화면 연결. 완료 기준은 재로그인 기록 유지·타인 접근 차단.

이번에는 **기록 작성 → 목록·상세 조회 → 같은 커트의 경과 추가**를 중심으로 설명. 서버 구조·ZIP·소셜 로그인·전체 커트 준비·Docker 기능을 별도 본문으로 늘리지 않음. 계정 백업 검증은 첫 장의 완료 기준 설명 한 문장, 상세 범위는 숨김 장과 질문 대응.

## 1장: 지난주 계획과 이번 주 결과

- React 입력·목록 화면 → 커트 입력·목록·상세 연결
- 커트·경과 저장·조회 → 기기 보관·재접속 후 재조회
- 같은 커트에 경과 추가 → 커트별 날짜·변화 기록 연결

약 40~50초:

> 지난주에는 커트와 경과를 저장하고 조회하는 기능을 React 입력·목록 화면과 연결하겠다고 말씀드렸습니다. 이번에는 커트 기록을 작성하고 목록과 상세에서 확인한 뒤, 같은 커트에 날짜별 경과를 추가하는 화면을 구현했습니다. 목업과 화면 구상에서 실제 조작하는 흐름으로 넘어간 단계입니다. 기록 유지와 계정 분리는 현재 기기 저장·계정 백업 범위에서 확인했습니다.

필요하면 짧게 추가: 작성 중 주 메뉴를 숨기고, 커트 정보·당일 기록·선택 정보를 나눠 입력 흐름 정리. 나가기는 초안을 유지하며, 명시적 내용 지우기와 구분.

## 2장: 커트 입력 → 조회 → 경과 추가

- 커트 작성: 날짜·부위·좋았던 점 입력
- 기록 조회: 저장된 카드와 상세 재진입
- 경과 추가: 같은 커트에 관찰 날짜·변화 기록

약 70~90초:

> 커트한 날짜와 부위, 좋았던 점을 입력하고 저장하면 목록과 상세에서 다시 확인할 수 있습니다. 이후 손질하면서 느낀 변화를 같은 커트의 경과로 추가합니다. 화면의 가상 사례는 10월 5일 커트에서 앞머리 길이가 마음에 들었지만, 일주일 뒤인 10월 12일에 옆머리가 다시 뜬 경우입니다. 처음 기록과 D+7 경과를 함께 볼 수 있고, 경과는 필요할 때만 작성합니다.

실제 조작을 하려면 캡처 설명 일부를 대체: 짧은 메모 → 저장 완료 → 목록·상세 → 경과 한 줄 → 같은 상세에서 확인. 저장 성공 화면을 기다린 뒤 새로고침. 로그인·파일 복원·전체 준비 과정으로 시연 시간을 늘리지 않음.

캡처는 새 비로그인 브라우저의 개인 기록. 사진 없는 최소 가상 기록이므로 사진 저장 완료의 시연 자료로 사용하지 않음. 입력·경과 상세는 실제 스크롤 위치의 화면.

## 3장: 피드백과 다음 개발

- 조원 시연: 입력·저장·조회에서 막힌 지점 확인
- 화면 보완: 문구·버튼·이동의 수정 순서 결정
- 다음 연결: 실제 디자이너 프로필 → 상담 요청·답변·이력
- 8주차: 시험 / 발표 없음

약 35~45초:

> 기록과 경과의 기본 흐름을 조원들이 직접 사용해 보고, 처음 진입과 입력·저장·이동에서 막힌 부분을 우선 확인할 예정입니다. 피드백을 받아 문구와 화면을 보완한 뒤 실제 디자이너 프로필과 상담 요청·답변을 연결하겠습니다. 8주차는 시험으로 발표가 없습니다. 다음 발표 범위와 일정은 피드백과 작업량을 보고 확정하겠습니다.

조원 피드백은 수집 전 상태. 개인 커트 준비 UI와 보관은 구현되어 있지만 실제 등록 디자이너·상담 송수신·후기 작성·커뮤니티는 후속. 구체적인 새 납기 약속 없음.

## 질문 대응

| 질문 | 답변 범위 |
|---|---|
| 기록이 실제로 남는가? | 개인 기록은 IndexedDB에 보관. 이번 캡처에서 저장·새로고침·목록과 상세 재진입 직접 확인 |
| 서버에도 저장하는가? | 로그인하면 계정별 암호화 백업 API로 자동 저장·복원. 별도 커트·경과 업무 CRUD와 상담 DB/API는 후속 |
| 타인 기록을 볼 수 없는가? | 현재 백업 API의 계정 소유권·기록/사진 분리 검증. 상담 참여자 권한이나 후속 도메인 API까지 완료했다고 주장하지 않음 |
| 테스트 개수가 사용성 점수인가? | 자동 검증 항목 수. 조원 피드백·외부 사용성 평가와 구분 |
