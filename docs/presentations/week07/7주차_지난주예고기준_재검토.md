| 구분 | 실제 발표 문구 |

| 당시 진행 중 | 데이터 구조(DB) 설계·구축 / 계정과 권한 |

발표자 노트도 **같은 커트에 경과를 추가하고 저장된 기록을 조회하는 기능과 입력·목록 화면 연결**을 예고. 서버 구조·암호화·백업 설정을 별도 발표하겠다는 내용은 없음.

11장의 전체 일정은 이후 상담 자료 선택·디자이너 프로필 → 1:1 메시지·상담 이력 순서. 이번 발표 기준은 12장의 다음 주 예고를 우선 적용.

## 이번 발표에서 보여줄 범위

**커트 기록 입력 → 저장된 기록 목록·상세 → 같은 커트에 경과 추가**를 중심으로 구성. 저장 결과는 이 화면 흐름에서 함께 확인. 서버 설명과 재로그인 시연을 별도 본문으로 추가하지 않음.

- 본문: 실제 React 입력·목록·상세, 같은 커트와 경과의 연결
- 짧은 보완 설명: 첫 진입 소개와 날짜·선택 정보 등 입력 편의 개선
- 완료 기준 보고: 기록 유지·계정 분리의 현재 확인 범위를 한 문장으로 설명
- 질문 대응: 계정 백업 방식·ZIP·소셜 로그인·검증 세부
- 다음 작업: 실제 디자이너 프로필·선택 자료·상담 연결

2~6주차는 문제·벤치마킹·서비스 흐름·개발 범위를 정리한 발표. 7주차는 지난주 목업과 구상에서 실제 조작 가능한 기록 화면으로 진행한 결과에 집중. 필요성·전체 서비스·장기 일정 재설명은 생략.

## 본문 3장 개조식 문구

### 1. 지난주 계획과 이번 주 결과

- 지난주 계획: 커트·경과 저장·조회 / React 입력·목록 연결
- 구현 결과: 커트 기록 입력·조회 / 같은 커트에 날짜별 경과 추가
- 화면 보완: 첫 진입 설명 / 입력 항목과 다음 행동 정리

발표 설명, 약 35~45초:

> 지난주에는 커트와 경과를 저장하고 조회하는 기능을 React 입력·목록 화면과 연결하겠다고 말씀드렸습니다. 이번에는 커트 기록을 작성하고 목록과 상세에서 확인한 뒤, 같은 커트에 경과를 추가하는 화면을 구현했습니다. 실제 조작하면서 첫 진입 설명과 입력 동작도 정리했습니다.

### 2. 커트 기록과 경과 작성 흐름

- 커트 기록: 날짜·부위·메모 입력 → 저장
- 기록 조회: 목록 → 커트 상세 확인
- 경과 추가: 같은 커트에 변화·불편한 점 기록
- 연결 확인: 커트와 날짜별 경과 함께 조회

발표 설명·화면 시연, 약 60~90초:

> 커트한 날의 기록을 남기면 목록과 상세에서 확인할 수 있습니다. 이후 손질하면서 느낀 변화를 같은 커트의 경과로 추가하고, 처음 기록과 함께 확인하도록 구성했습니다. 경과는 필요할 때만 작성할 수 있습니다.

저장·권한 관련 보고는 다음 한 문장으로 제한:

> 기록 유지와 계정 분리는 현재 기기 저장·계정 백업 범위에서 확인했습니다.

화면을 보여주는 순서:

1. 미리 준비한 발표용 커트 입력값에서 메모 한 줄 변경·저장
2. 목록과 해당 커트 상세 확인
3. 같은 커트에 경과 한 줄 추가·저장
4. 상세에서 커트와 경과의 연결 확인

여유가 있으면 새로고침 후 같은 자료가 남는 모습만 확인. 로그인 입력·계정 전환·ZIP 복원·3단계 커트 준비까지 시연을 늘리지 않음. 로그인한 시연 계정을 사용할 경우 사전에 서버 저장 상태 확인. 인터넷·서버 상태와 관계없이 설명할 수 있도록 같은 흐름의 캡처 준비.

### 3. 남은 작업과 다음 순서

- 현재 단계: 개인 기록·경과 작성과 조회
- 다음 연결: 실제 디자이너 목록·프로필 / 선택 자료
- 이후 구현: 상담 요청·답변·이력
- 8주차: 시험 / 발표 없음

발표 설명, 약 30~40초:

> 기록 화면을 기반으로 다음에는 실제 디자이너 프로필과 선택한 자료를 연결할 예정입니다. 이후 요청을 보내고 디자이너가 답변하는 상담 흐름으로 이어가겠습니다. 상담 전송과 답변은 아직 구현 전이며, 8주차는 시험으로 발표가 없습니다.

다음 개발 순서는 제안. 구체적인 범위·일정과 상담 자료의 서버 저장·접근 계약은 구현 전에 확정.

## 저장 설명의 정확한 경계

기존 7주차 자료의 **기록이 메모리에만 있고 새로고침·로그인 전환 시 사라진다**는 문구는 10/10 상태. 최신 개인 영역에는 기기 보관과 계정 자동 저장이 구현되어 있어 해당 설명 수정 필요. 예시 체험은 계속 메모리 전용.

현재 서버에는 개인 기록·사진을 보관·복원하는 **계정별 암호화 백업 API**가 존재. 별도의 커트·경과 업무 CRUD API와 도메인 테이블은 후속. 발표에서 서버 저장 질문이 나오면 아래처럼 설명:

> 개인 자료는 기기에 보관하고, 로그인하면 계정별로 서버에 자동 백업합니다. 현재 서버 저장은 개인 백업 방식이며, 커트·경과 업무 API와 상담 저장은 후속 범위입니다.

재로그인·새 브라우저 환경의 복원과 다른 계정 분리는 계정 백업 범위에서 검증. 이를 상담 참여자 권한 검증이나 전체 업무 API 완료로 확대하지 않음. 커트·경과의 기기 재접속 검사와 계정의 기록·사진·초안 복원 검사는 별도 시나리오이므로, 모든 자료를 묶은 하나의 통합 시연이 완료됐다고 주장하지 않음.

## 기존 7주차 안에서 바꿀 부분

- 6장 예시안: 기기 보관 방향·새 첫 화면·장기 계획 비중이 커서 이번 진행 보고의 본문으로 사용하기 어려움
- 4장 진행보고안: 개발 중 UI 보완을 독립 장으로 다루고 커트 준비까지 시연해 이번 주 예고보다 범위가 넓음
- 두 안의 저장 미구현·메모리 전용 설명: 최신 상태와 불일치
- 권장 수정: 본문 3장, 기록·경과 입력·조회 시연 중심, 저장·권한은 확인 범위 한 문장
- 이번 작업: 발표 범위와 문구 재검토 문서 작성. 기존 PPTX/PDF·원본 발표 자료·제품 코드 변경 없음
