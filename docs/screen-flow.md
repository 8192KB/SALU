# 화면 흐름

여러 사람이 기능을 나눠 만들어도 화면 이동이 어긋나지 않도록 지금 있는 화면과 이동을 한곳에 적습니다. 새 화면이나 이동을 만들 때는 코드보다 이 문서를 먼저 고치고, PR에서 흐름을 확인받은 뒤 구현합니다.

## 새 화면을 만들 때

1. 아래 표에 화면을 추가합니다. 주소, 속한 메뉴, 들어오는 곳, 다음 화면, 위쪽 뒤로 링크의 기본값을 적습니다.
2. 주소 규칙을 맞춥니다. 작성 화면은 `frontend/src/main-navigation.tsx`의 `isTaskPath`, 완료 화면은 같은 파일의 `isCompletionPath`와 `frontend/src/back-trail.ts`의 `skipped` 규칙에 맞는 주소를 씁니다. 이 규칙이 메뉴별 마지막 화면, 스크롤 복원, 뒤로 링크를 정합니다. 새 작성·완료 주소를 만들면 이 규칙도 같이 고칩니다.
3. 공통 부품을 씁니다. 제목은 `PageHeading`, 위쪽 뒤로 링크는 `BackLink`, 저장·전송 완료는 `completion.tsx`의 공통 완료 화면입니다.
4. 예시 체험(`/examples/*`)에서도 보여야 하는지 정합니다. 예시는 메모리 저장소만 쓰고 서버에 보내지 않습니다.
5. 하단 메뉴 항목을 늘리거나 바꾸는 일은 Issue에서 먼저 합의합니다.

## 공통 이동 규칙

자세한 기준은 [개발 계약](development-contract.md)의 화면과 자료 항목에 있습니다.

- 위쪽 뒤로 링크는 그 화면을 열기 직전에 보던 화면으로 돌아갑니다. 새로고침하면 표의 기본값으로 갑니다.
- 작성 화면의 나가기는 몇 단계째든 작업을 시작한 화면으로 돌아갑니다.
- 완료 화면은 한 번 보는 화면이라 뒤로 링크가 돌아갈 곳으로 기억하지 않습니다.
- 메뉴를 오가면 메뉴별 마지막 화면과 스크롤을 유지합니다. 지금 메뉴를 다시 누르면 그 메뉴의 첫 화면으로 갑니다.
- 디자이너 화면(`/designers/*`)은 들어온 메뉴에 속합니다.

## 메뉴

터치 기기는 하단 메뉴, 데스크톱은 상단 메뉴입니다.

| 메뉴 | 첫 화면 | 비고 |
|---|---|---|
| 홈 | `/` | 예시 체험에는 없음 |
| 내 기록 | `/records` | |
| 커트 준비 | `/requests` | |
| 상담 | `/consultations` | 상담 내역 |
| 내 계정 | `/account` | 하단 메뉴가 아니라 머리글의 회원 이름 링크로 들어감 |

## 지금 있는 화면

작성은 작성 화면(`isTaskPath`), 완료는 완료 화면입니다.

### 홈·계정

| 주소 | 화면 | 들어오는 곳 | 다음 |
|---|---|---|---|
| `/` | 홈 | 메뉴 | 새 기록, 내 기록, 예시 체험 |
| `/login`, `/signup` | 로그인·회원가입 | 머리글, 계정이 필요한 화면 | 로그인 뒤 홈 |
| `/account` | 내 계정 | 머리글 회원 이름 | 저장 상태, 받은 상담(디자이너만), 내 디자이너 프로필 |
| `/account/designer` | 내 디자이너 프로필 | 내 계정 | 저장 뒤 내 계정 |
| `/backup` | 저장 상태·ZIP | 기록 목록, 내 계정 | |

### 내 기록

| 주소 | 화면 | 들어오는 곳 | 다음 | 뒤로 기본값 |
|---|---|---|---|---|
| `/records` | 기록 목록 | 메뉴 | 기록 상세, 새 기록 | |
| `/records/new` | 커트 작성(작성) | 홈, 기록 목록 | 저장 → 완료 | 나가기: 시작한 화면 |
| `/records/:id/edit` | 커트 수정(작성) | 기록 상세 | 저장 → 완료 | 나가기: 시작한 화면 |
| `/records/:id/complete` | 커트 저장 완료(완료) | 커트 작성·수정 | 기록 상세 | |
| `/records/:id` | 기록 상세 | 기록 목록, 완료 | 다음 커트 준비(주 버튼), 경과 추가, 수정, 담당 디자이너 프로필·상담(보조) | 기록 목록 |
| `/records/:id/progress/new`, `/records/:id/progress/:progressId/edit` | 경과 작성(작성) | 기록 상세 | 저장 → 완료 | 나가기: 시작한 화면 |
| `/records/:id/progress/:progressId/complete` | 경과 저장 완료(완료) | 경과 작성 | 기록 상세 | |

### 커트 준비

| 주소 | 화면 | 들어오는 곳 | 다음 | 뒤로 기본값 |
|---|---|---|---|---|
| `/requests` | 준비 목록 | 메뉴, 기록 상세 | 자료 선택, 준비 내용 | |
| `/requests/materials` | 자료 선택(작성) | 준비 목록, 기록 상세 | 요청 작성 | 나가기: 시작한 화면 |
| `/requests/write` | 요청 작성(작성) | 자료 선택 | 저장 전 확인 | 이전 단계 |
| `/requests/review` | 저장 전 확인(작성) | 요청 작성 | 저장 → 완료 | 이전 단계 |
| `/requests/complete/:id` | 준비 저장 완료(완료) | 저장 전 확인 | 준비 내용 | |
| `/requests/previews/:id` | 준비 내용 | 준비 목록, 완료 | 고른 디자이너에게 상담 작성, 디자이너 찾기 | 준비 목록 |

### 상담

| 주소 | 화면 | 들어오는 곳 | 다음 | 뒤로 기본값 |
|---|---|---|---|---|
| `/consultations` | 상담 내역(보낸 상담) | 메뉴 | 보낸 상담 상세, 받은 상담(디자이너만) | |
| `/designers` | 디자이너 찾기 | 커트 준비, 기록 상세, 준비 내용 | 디자이너 상세 | 들어온 화면 |
| `/designers/:id` | 디자이너 상세 | 디자이너 찾기, 기록 상세 | 상담 작성 | 들어온 화면. 기록에서 오면 커트 기록 |
| `/consultations/new` | 상담 작성(작성) | 디자이너 상세, 준비 내용 | 요청 보내기 → 완료 | 나가기: 시작한 화면 |
| `/consultations/:id/complete` | 전달 완료(완료) | 상담 작성 | 보낸 상담 상세, 상담 내역 | |
| `/consultations/:id` | 보낸 상담 상세 | 상담 내역, 완료 | | 상담 내역 |
| `/consultations/received` | 받은 상담 목록 | 상담 내역, 내 계정 | 받은 상담 상세 | 상담 내역 |
| `/consultations/received/:id` | 받은 상담 상세 | 받은 상담 목록 | 답변 보내기 → 완료 | 받은 상담 목록 |
| `/consultations/received/:id/complete` | 답변 완료(완료) | 받은 상담 상세 | 받은 상담 목록 | |

예시 체험은 `/examples` 아래에 같은 주소를 씁니다. 예시에는 홈이 없고 받은 상담도 없습니다.

## 새 기능이 붙을 자리

기능 Issue에서 확정하기 전의 제안입니다. 확정되면 위 표로 옮깁니다.

| 기능 | 붙을 자리 | 새 화면 |
|---|---|---|
| 상담 대화 | 보낸 상담 상세와 받은 상담 상세 안에 대화 목록과 입력칸. 첫 답변 뒤의 메시지는 완료 화면 없이 같은 화면에 바로 추가 | 없음 |
| 알림 | 머리글의 알림 버튼과 안 읽은 수. 항목을 누르면 상담 상세 같은 대상 화면으로 이동 | `/notifications` |
| 디자이너 후기 | 답변을 받은 보낸 상담 상세 → 후기 작성 → 완료 → 디자이너 상세의 후기 구역 | `/consultations/:id/review`(작성), 완료 화면 |
| 찜 | 디자이너 상세의 찜 버튼, 디자이너 찾기의 찜한 디자이너 보기 | 없음 |
| 소속 이력 | 디자이너 상세의 프로필 구역에 이전 소속 | 없음 |
| 커뮤니티 | 하단 메뉴 추가 여부를 먼저 합의. 기록 상세에서 사례로 공개하는 진입 | `/community`, `/community/:id`, `/community/new`(작성) |
| 관리자 | 관리자 계정의 내 계정에서만 진입. 신고 목록·처리 | `/admin/*` |
