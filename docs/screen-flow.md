# 화면 흐름

여러 사람이 기능을 나눠 만들어도 화면 이동이 어긋나지 않도록 지금 있는 화면과 이동을 한곳에 적습니다. 새 화면이나 이동을 만들 때는 코드보다 이 문서를 먼저 고치고, PR에서 흐름을 확인받은 뒤 구현합니다.

## 새 화면을 만들 때

1. 아래 표에 화면을 추가합니다. 주소, 속한 메뉴, 들어오는 곳, 다음 화면, 위쪽 뒤로 링크의 기본값을 적습니다.
2. 주소 규칙을 맞춥니다. 작성 화면은 `frontend/src/main-navigation.tsx`의 `isTaskPath`, 완료 화면은 같은 파일의 `isCompletionPath`와 `frontend/src/back-trail.ts`의 `skipped` 규칙에 맞는 주소를 씁니다. 이 규칙이 메뉴별 마지막 화면, 스크롤 복원, 뒤로 링크를 정합니다. 새 작성·완료 주소를 만들면 이 규칙도 같이 고칩니다.
3. 공통 부품을 씁니다. 제목은 `PageHeading`, 위쪽 뒤로 링크는 `BackLink`, 저장·전송 완료는 `completion.tsx`의 공통 완료 화면입니다.
4. 예시 체험(`/examples/*`)에서도 보여야 하는지 정합니다. 예시는 메모리 저장소만 쓰고 서버에 보내지 않습니다.
5. 하단 메뉴 항목을 늘리거나 바꾸는 일은 조원과 먼저 합의합니다.

## 공통 이동 규칙

- 위쪽 뒤로 링크는 그 화면을 열기 직전에 보던 화면으로 돌아가고, 보던 스크롤 위치도 그대로입니다. 이 기억은 탭에만 있어서 새로고침하면 표의 기본값으로 갑니다.
- 단계가 정해진 작성 화면의 뒤로 링크는 이전 단계이고, 이름도 단계 표시와 같습니다(`자료 고르기`, `상담 내용 적기`·`원하는 점 적기`). 작성·완료 화면을 거쳐 온 화면은 기본값으로 갑니다. 커트 준비 목록에서 지난 커트를 골라 시작하면 자료 선택의 뒤로 링크는 고르던 화면입니다.
- 작성 화면의 나가기는 몇 단계째든 작업을 시작한 화면으로 돌아갑니다.
- 알림 목록과 상담 대화 말풍선의 시각은 오늘이면 `오전 1:09`, 올해면 `11월 6일 오전 1:09`, 그 밖은 `2026. 11. 6. 오전 1:09`처럼 줄여 보이고 전체 시각은 마우스를 올리면 보입니다. 목록·상세의 등록·보낸 시각은 전체 형식입니다.
- 브라우저 탭 제목은 화면 제목(`PageHeading`의 h1) 뒤에 `| SALU`를 붙인 것입니다. 화면 제목 아래 오류·로그인 안내는 h2라 제목이 하나만 있습니다.
- 완료 화면은 한 번 보는 화면이라 뒤로 링크가 돌아갈 곳으로 기억하지 않습니다. 완료 화면에 오면 그 메뉴에 남겨 둔 작성 화면도 버려, 다시 열면 빈 작성 화면입니다.
- 위쪽 뒤로 링크와 완료 화면 버튼이 가리키는 곳이 방문 기록 바로 앞이면 새로 쌓지 않고 뒤로 가서, 브라우저 뒤로 가기가 두 화면을 왕복하지 않습니다. 작성 화면 `나가기`는 뒤로 가기로 작성 화면에 돌아올 수 있게 기록을 남깁니다.
- 커뮤니티 분류·찜한 디자이너만 보기처럼 같은 화면에서 주소 뒤 조건만 바꾸면 화면 이동으로 보지 않아 초점을 누른 버튼에 남깁니다(같은 버튼을 못 찾으면 화면 제목).
- 커트 준비를 저장한 뒤 브라우저 뒤로 가기로 앞 단계(자료 고르기·원하는 점 적기)에 돌아오면 그 준비 내용으로 한 번만 바뀌고, 다시 뒤로 가면 준비를 시작한 화면입니다.
- 글쓰기·후기·답변·댓글·상담 메시지의 보내기 전 입력은 이 탭에 남아 새로고침이나 세션 끊김 뒤 다시 로그인해도 이어 씁니다. 직접 로그아웃하면 지웁니다.
- 기록 상세의 `이 기록 지우기`, 경과 수정의 `이 경과 지우기`, 수정 화면 저장 사진의 `지우기`는 확인창을 거쳐 바로 지웁니다. 지우면 그 기록으로 만든 준비 내용에서도 빠지고, 기록을 지우면 기록 목록으로 갑니다. 이미 보낸 상담과 올린 글의 사본은 그대로입니다.
- 작업 시작 위치와 뒤로 링크 기억은 탭 저장소에 남아 새로고침해도 유지되고, 탭을 닫거나 직접 로그아웃하면 사라집니다.
- 신고 처리 화면 아래 `숨긴 글·댓글`에서 처리가 끝난 숨김도 다시 보이게 할 수 있습니다.
- 자료만 고르고 글을 쓰지 않은 준비 초안은 참고할 커트를 바꾸면 비워 `작성 중`에 쌓이지 않습니다. 글을 쓴 초안은 커트별로 남습니다.
- 메뉴를 오가면 메뉴별 마지막 화면·초안·스크롤을 유지합니다. 지금 메뉴를 다시 누르면 그 메뉴의 첫 화면으로 가지만 초안은 지우지 않습니다.
- 이 화면 보관은 접속 중에만 있고 기기 자료 보관과는 별개입니다. 계정이나 예시 공간을 바꾸면 이전 공간의 화면은 버립니다.
- 디자이너 화면(`/designers/*`)은 들어온 메뉴에 속합니다.
- 디자이너로 활동하는 화면(받은 상담 `/consultations/received*`, 내 디자이너 프로필 `/account/designer*`)은 디자이너 색으로 보입니다. 같은 회원이 고객으로도 쓰므로 로그인한 계정이 아니라 주소로 정합니다. 고객이 보는 디자이너 찾기·상세는 고객 화면입니다.

## 메뉴

터치 기기는 하단 메뉴, 데스크톱은 상단 메뉴입니다.

| 메뉴 | 첫 화면 | 비고 |
|---|---|---|
| 홈 | `/` | 예시 체험에는 없음 |
| 내 기록 | `/records` | |
| 커트 준비 | `/requests` | |
| 상담 | `/consultations` | 상담 내역 |
| 더보기 | `/more` | 커뮤니티·찜한 디자이너·디자이너 활동(받은 상담·내 디자이너 프로필, 디자이너 색)·알림·내 계정 바로가기. 하단 메뉴 맨 오른쪽. 예시 체험에는 없음. 커뮤니티 화면(`/community/*`)도 이 메뉴에 속함 |
| 내 계정 | `/account` | 하단 메뉴가 아니라 머리글의 회원 이름 링크로 들어감. 머리글 `로그아웃`은 바로 로그아웃하고, 서버에 아직 올리지 못한 기록이 있을 때만 확인 창을 띄움 |

## 지금 있는 화면

작성은 작성 화면(`isTaskPath`), 완료는 완료 화면입니다.

### 홈·계정

| 주소 | 화면 | 들어오는 곳 | 다음 |
|---|---|---|---|
| `/` | 홈 | 메뉴 | 새 기록, 내 기록, 예시 체험 |
| `/login`, `/signup` | 로그인·회원가입. 회원가입은 이메일 `중복 확인` 버튼, 비밀번호 보기, 확인 칸 실시간 일치 표시. 로그인 양식 아래 `비밀번호를 잊었나요?`(돌아올 곳 유지). 뒤로 링크는 돌아올 곳이 작성 화면이면 그 메뉴의 목록. 돌아갈 화면은 상세 이름으로 부름(`디자이너 프로필로`, `커트 기록으로`, `준비 내용으로` 등) | 머리글, 계정이 필요한 화면 | 로그인 확인, 비밀번호 찾기 |
| `/password-reset` | 비밀번호 찾기. 이메일을 넣으면 가입 여부와 상관없이 `메일을 보냈어요`. 메일 링크(`#token=…`)로 들어오면 새 비밀번호·확인 칸 → `비밀번호를 바꿨어요`. 토큰은 읽은 뒤 주소에서 지움. 만료·사용한 링크면 `새 링크 받기`로 이메일 칸을 다시 보여 줌. 로그인에서 왔으면 돌아올 곳을 로그인까지 넘김 | 로그인, 메일 링크 | 로그인 |
| `/auth/complete` | 로그인 확인. 이 기기에 로그인 전 기록이 있으면 최근 기록 3개를 보여 주고 계정으로 옮길지 물음(이 기기에서 계정마다 한 번. 그 뒤 로그인 전 기록·사진이나 쓰던 새 기록 내용이 새로 생기면 다시 물음) | 로그인·회원가입·소셜 로그인 | 들어온 화면이나 홈. 옮기지 않았는데 들어온 화면이 로그인 전 기록이면 내 기록 |
| `/account` | 내 계정. 이름 바꾸기, 비밀번호 바꾸기(이메일로 가입한 계정만)는 이 화면 안에서 열고 저장 | 머리글 회원 이름 | 기록 백업, 디자이너 활동 구역(디자이너 색): 받은 상담(디자이너만), 내 디자이너 프로필 |
| `/account/designer` | 내 디자이너 프로필. 전문 분야는 정해진 시술 항목을 눌러 최대 5개 고름(직접 쓰지 않음. 목록 밖의 예전 값은 `예전에 적은 분야`로 보여 주고 저장하면 빠짐). 상담 요금 칸(원, 1,000원 단위, 0원이면 무료). 매장 등록 칸의 `주소 검색`(Daum 우편번호를 칸 안에 펼침)으로 위치를 넣고, 위치 없는 매장을 고르면 `이 매장 위치 넣기`(처음 등록한 회원만). 지도 키가 없으면 주소 칸 없음. 저장하면 완료 화면, 비공개면 `디자이너 찾기로` 없이 `내 계정으로`만 | 내 계정 | 저장 뒤 내 계정 |
| `/backup` | 기록 백업. 계정 자동 저장·ZIP. 복원할 때 이미 있는 같은 기록은 건너뛰고 몇 건을 건너뛰었는지 알림. 로그인했고 이 기기에 로그인 전 기록이 남아 있으면 최근 기록 3개를 보여 주고 계정으로 옮기기 | 기록 목록, 내 계정, 로그인 확인의 안내 | |
| `/notifications` | 알림 목록. 모두 읽음 | 머리글 알림 버튼(로그인했을 때만, 작성 화면·예시 체험에서는 숨김) | 항목을 누르면 읽음 처리 후 대상 화면(상담 상세 등). 디자이너로 받은 알림(상담 요청, 받은 상담 메시지, 후기)은 디자이너 색과 `디자이너` 표시 |

### 내 기록

| 주소 | 화면 | 들어오는 곳 | 다음 | 뒤로 기본값 |
|---|---|---|---|---|
| `/records` | 기록 목록. 기록이 없으면 커트 준비 링크를 숨기고 백업(복원) 링크만 둠 | 메뉴 | 기록 상세, 새 기록 | |
| `/records/new` | 커트 작성(작성) | 홈, 기록 목록 | 저장 → 완료 | 나가기: 시작한 화면 |
| `/records/:id/edit` | 커트 수정(작성) | 기록 상세 | 저장 → 완료 | 나가기: 시작한 화면 |
| `/records/:id/complete` | 커트 저장 완료(완료). 디자이너 상담 중에 기록을 남기거나 담당을 연결하러 왔으면(`?consult=`) 주 버튼이 `○ 디자이너에게 상담 신청`(담당이면 상담 신청, 아니면 그 디자이너 상세). 커뮤니티 글쓰기의 `기록부터 남기기`에서 왔으면(`?share=1`) 주 버튼이 `이 기록으로 사례 글 쓰기`(그 기록을 고른 글쓰기) | 커트 작성·수정 | 기록 상세, 내 기록 | |
| `/records/:id` | 기록 상세 | 기록 목록, 완료 | 다음 커트 준비(주 버튼), 경과 추가, 수정, 담당 디자이너 프로필·상담(보조), 작성 중인 디자이너 상담 신청 이어쓰기(개인 준비 이어쓰기와 따로), 커뮤니티에 사례로 올리기(실제 공간) | 기록 목록. 준비 내용의 `원본 기록 보기`에서 오면 뒤로 링크는 그 전 화면 |
| `/records/:id/progress/new`, `/records/:id/progress/:progressId/edit` | 경과 작성(작성) | 기록 상세 | 저장 → 완료 | 나가기: 시작한 화면 |
| `/records/:id/progress/:progressId/complete` | 경과 저장 완료(완료) | 경과 작성 | 기록 상세 | |

### 커트 준비

| 주소 | 화면 | 들어오는 곳 | 다음 | 뒤로 기본값 |
|---|---|---|---|---|
| `/requests` | 준비 목록 | 메뉴, 기록 상세 | 자료 선택, 준비 내용 | |
| `/requests/materials` | 자료 선택(작성). 디자이너 상세에서 시작하면 지난 커트 고르기부터 고른 디자이너와 상담 요금(`상담 1회 ○원`, 요금이 붙을 때만)을 함께 보여 줌(`/consultations/materials`도 같은 화면). 경과가 없어도 당일 메모나 사진 하나면 넘어감. 고를 자료가 하나도 없는 기록은 고르지 않고 넘어감(날짜·시술만 첨부). 기록이 없으면 `커트 기록 남기기`가 그 디자이너 상담으로 돌아올 길을 넘김 | 준비 목록, 기록 상세, 디자이너 상세 | 요청 작성 | 나가기: 시작한 화면 |

| `/community/mine` | 내 글. 이용 제한 중이면 맨 위에 기간·이유. 숨겨진 글은 `숨김 · 신고가 쌓여 검토 중이에요`(자동 숨김) 또는 `숨김 · 운영 기준에 따라 숨겼어요`(관리자 확정)로 보이고 열리지 않음. 들어오면 숨김·제재 알림을 읽음 처리 | 커뮤니티 목록, 더보기, 숨김·제재 알림 | 글 상세 | 커뮤니티 |

### 관리자

`/api/auth/me`의 `role`이 `ADMIN`인 계정만 더보기에 `신고 처리`가 보입니다. 다른 계정이 주소로 들어오면 `관리자만 볼 수 있어요`이고, 실제 권한은 서버가 다시 확인합니다. 관리자 지정은 DB에서만 합니다.

| 주소 | 화면 | 들어오는 곳 | 다음 | 뒤로 기본값 |
|---|---|---|---|---|
| `/admin/reports` | 처리 전 신고가 있는 글·댓글. 댓글은 이 화면에서 신고 내용 보기(다시 누르면 접기)·숨기기 → 확인 창·유지. 숨기기·유지 버튼은 같은 모양이고 빨간 버튼은 확인 창에만 둠, 처리하면 결과 안내와 함께 목록에서 빠짐 | 더보기 | 신고된 글, 작성자 제재 기록 | 더보기 |
| `/admin/posts/:id` | 신고된 글 내용(숨김·삭제 포함)과 신고 목록. 숨기기 → 확인 창·유지(숨김이면 다시 보이기 → 확인 창). 처리하면 결과 안내, 버튼은 지금 상태에 맞게 바뀜. 작성자가 지운 글은 신고 받아들이기·기각 | 신고 처리 | 작성자 제재 기록 | 신고 처리 |
| `/admin/members/:id` | 회원 제재 기록, 새 제재(3·7·30일·기간 없음, 이유. 이유는 회원에게 보임) → 확인 창, 해제 → 확인 창. 제재 중이면 새 제재 칸 대신 해제 안내. 내 계정이면 제재 칸 없이 안내만 | 신고 처리, 신고된 글 | | 신고 처리 |

### 오류 화면

어느 메뉴에서든 같은 모양(`ErrorState`)입니다. 제목은 무슨 일인지, 설명은 다음에 할 일을 한 줄로 말하고, 버튼은 갈 수 있는 곳만 둡니다.

| 언제 | 화면 | 버튼 |
|---|---|---|
| 앱에 없는 주소 | 페이지를 찾을 수 없어요 | 홈으로, 이전 화면(뒤로 갈 곳이 있을 때) |
| 서버가 대상이 없다고 함(404, 지워진 글·없는 상담·없는 준비) | ○○을 찾을 수 없어요 | 그 메뉴의 목록 |
| 로그인 전에 계정 자료 주소를 엶(로그아웃 뒤 뒤로 가기 등) | ○○을 찾을 수 없어요, 계정에 저장한 자료라면 로그인하면 볼 수 있다는 안내 | 그 메뉴의 목록, 로그인(이 주소로 돌아옴) |
| 로그인이 필요함(401) | 로그인이 필요해요 | 로그인(돌아올 곳 유지) |
| 권한 없음(403, 관리자 전용) | ○○만 볼 수 있어요 | 그 사람이 갈 수 있는 첫 화면 |
| 서버 연결 실패·500 | 잠시 연결할 수 없어요 | 다시 시도 |
| 화면을 그리다 멈춤 | 화면을 보여 주지 못했어요 | 다시 불러오기, 홈으로 |
